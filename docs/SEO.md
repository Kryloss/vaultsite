# SEO, feeds, identity and analytics

All statically generated. Reasons: `docs/DECISIONS.md` #8, #31, #33, #40, #41, #43, #57, #78, #106.

- `app/sitemap.ts`, `app/robots.ts`, `app/feed.xml/route.ts` (RSS for Posts). Site origin: `siteUrl` in `lib/site-config.ts`. Shelf medium, category, and studio pages are in the sitemap; they have no OG image of their own and inherit the site default.
- Every page sets its own `<link rel=canonical>` + `og:url` through `pageMeta()` in `lib/metadata.ts`; notes also get `og:type=article` with `article:published_time`. Without a canonical the `?lang=uk` links `SelectionLink` hands out are indexable duplicates. `pageMeta()` re-declares the RSS link and `og:site_name` because Next REPLACES `alternates`/`openGraph` rather than merging them (#43). Preserve JSON-LD, sitemap, RSS and OG-image behaviour when adding routes or content types.
- **Identity**: `socials` in `lib/site-config.ts` is the ONE list of the owner's accounts, and both machine-readable claims read it — `rel="me"` on every icon link (`components/SocialLinks.tsx`, the IndieWeb claim Mastodon checks) and `sameAs` in the JSON-LD (the search-engine one, which drops the `mailto:` since it isn't a profile). Never put someone else's profile in that list: it would inherit `rel="me"` and claim to be them (#78).
- **JSON-LD** in `lib/jsonld.ts`: `siteJsonLd()` (Person + `sameAs` socials, WebSite) in the layout, `entryJsonLd()` per note, `breadcrumbJsonLd()` on section and entry pages (home has none — it's the root of every trail; two levels is the whole hierarchy, English names only, #40). A video note is a `VideoObject` only when `videoObject()` can build the complete object (`uploaded:` supplies `uploadDate`, `embedUrl` not `contentUrl`), otherwise `CreativeWork` — nothing can emit a half-populated `VideoObject`, which Google treats as an error (#41). Music notes are `MusicAlbum` with `byArtist`; rated entries are wrapped in a `Review`.
- **OG images** generated at build via `next/og` — shared renderer in `lib/og.tsx`, route files `app/opengraph-image.tsx` + per-section + per-entry. Every route gets the same editorial vault card: embedded Source Serif 4 (static TTFs in `assets/fonts/`, build inputs only), the favicon's monochrome double-chevron redrawn from `app/icon.svg` as inline paths (if the favicon's geometry changes, both copies must change together), a deterministic 5×4 dot fingerprint from the title, inset registration marks, and an oversized watermark on text cards. Artwork is the only colour — do not introduce section accent colours. Shelf and Music entries mount their own art on an offset plate shaped by `coverShape` (`tall` | `wide` | `square`, a lookup rather than booleans); the image itself uses `contain`, so a real jacket or poster is never cropped to the approximate frame. People remain text-only — a person's portrait is not a cover to paste onto a social card. `ogCover()` inlines vault images as data URLs (relative paths don't resolve at build time) and returns undefined for anything Satori can't decode (no WebP or AVIF), so the note quietly falls back to the text card rather than failing the build (#57, #106). The entry card's subtitle reads `Kyrylo · Music`, owner first like the breadcrumb (#92).
- **Favicon**: `app/icon.svg` is the double-chevron mark in one neutral grey (`#71717a`) on transparency, so it stays monochrome against either light or dark browser chrome. `app/apple-icon.png` remains the owner's avatar for home-screen installs.
- **Analytics**: `@vercel/analytics` in the root layout — page views, no cookies; it puts one `BAILOUT_TO_CLIENT_SIDE_RENDERING` template in every prerendered page and nothing else (#31). The layout also ships a `speculationrules` script that **prefetches** internal documents on hover — never `prerender`, which would run the page and make every hover count as a visit, since `@vercel/analytics` does not check `document.prerendering` (#33).
- The Cmd+K "open on GitHub" action depends on the repo being public — `docs/CHROME.md`.
