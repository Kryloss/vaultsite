# Local authoring dock

The one exception to "no runtime fs access", and it lives outside the deployed site: `npm run dev` (`scripts/dev.mjs`) supervises Next plus a writer on `127.0.0.1` (`scripts/dev-editor.mjs`, `dev-editor-server.mjs`, `dev-editor-core.mjs`). Production has no rewrite, no writer, and `next.config.ts` aliases every dev component to a null/static replacement. Reasons and contract: DECISIONS #118, #119, #122. Replaced the 2026-08-29 change report; its verification log is in `git log`.

## Rules

- **Use `npm run dev`, never bare `next dev`**, and restart it after changing sidecar code — the sidecar does not hot-reload. `/session` reports `EDITOR_PROTOCOL` (one number, in `scripts/dev-editor-core.mjs` and `lib/dev-tools.ts`, equal by test); bump it when endpoints or payloads change, and a browser talking to an older process shows "restart `npm run dev`" instead of failing request by request (a 404 from an unknown endpoint is treated the same way).
- **The sidecar renders with the site's own pipeline.** `scripts/dev.mjs` starts it with type stripping and the `@/` resolver from `scripts/test-hooks.mjs`, so `/preview` can import `lib/markdown.ts` and render a draft exactly as `app/[section]/[slug]/page.tsx` would (same options: fact tables, lifted facts, the rating row, `uk-` id prefix). Loaded lazily; without those flags the endpoint answers 501 `preview_unavailable` and the editor works without live preview.
- Available only when all three hold: development build, `window.location.hostname === "localhost"` exactly, sidecar running. The sidecar independently checks the exact supervisor origin, same-origin fetch metadata, and a random session token (`X-Vault-Editor-Token`); JSON only, bounded bodies, no CORS.
- **A URL never becomes a write path.** Sources come from `data-dev-vault-source` / `data-dev-body-field` markers on the page; the writer accepts only existing `.md` paths under `vault/`, rejects traversal/backslashes/NUL, resolves symlinks with realpath and rechecks containment. The Ukrainian path must be the primary's `.uk.md` sibling.
- **Prose is edited in the rendered text where the render round-trips, and as source where it does not.** A press on a paragraph, heading, list item, quote or callout makes THAT ELEMENT `contentEditable` (`rich` mode): its DOM is serialised back to Markdown on every input (`richMarkdown()` — emphasis, strike, code, wiki links by the page's href → title index, plain and bare links, vault image embeds by basename, footnote marks, hard line breaks (`<br>` → `  ⏎`; a run of them → a paragraph boundary); a heading's anchor, a sidenote copy, a task checkbox and a nested list are skipped and frozen) and spliced under the block's own syntax (`splitRichShape()`/`joinRichShape()` in `lib/dev-tools.ts`: `## `, `- [ ] `, `> ` on every line, a callout's header). The mode is chosen per block by a test, not a list: render-then-serialise must give the source body byte for byte, else the block opens as its Markdown in a textarea standing in its place (`block` mode — code fences, tables, images, anything with syntax the serialiser does not cover). Enter is a line break (two in a row split the paragraph on render); Cmd+B/I use the browser's own bold/italic; the other tools type their Markdown at the caret and it renders when the block closes; `[[` suggestions read the caret's text node. The caret lands where the press was (`caretPositionFromPoint`). Leaving the block (Esc, Cmd+Enter, Done, a press elsewhere, focus leaving for anything but the bar) closes it and the article re-renders. The rest of the article stays rendered. **The article is not repainted while a block is open**: nothing outside the block can change, the block is hidden, and replacing the HTML would pull the editor out of the document for an instant — long enough for the browser to drop its focus mid-word (the first real keystroke found this; synthetic events had not). The fact containers keep repainting, and the article catches up the moment the block closes. A block in `rich` mode needs no preview: the text IS the render, and no preview request is made for its article until it closes; the catch-up render then goes without the debounce. Nothing the dock draws has an outline or a ring any more — the caret is the whole affordance; the source field for a non-invertible block is told apart by its monospace type alone. A press below the text starts a new paragraph at the end. Esc, Cmd+Enter or the Done button render the block; ↑ on the first line or ↓ on the last moves to the neighbouring block; Backspace in an empty block removes it (an empty block never leaves a blank line behind). The article's server HTML is snapshotted with the dock's own additions stripped (`snapshotHtml()`) BEFORE a mount goes in — restoring a snapshot that carried the mount re-created a textarea React no longer owned. The block's source range comes from `blockSourceRange()` (`lib/dev-tools.ts`: the block's first words locate it, its kind says how far it reaches); a block that cannot be matched (raw HTML, a repeated paragraph) opens the whole source instead. **Source** in the tools bar opens the whole body in the bar with the article as live preview above (the earlier drawer); a press on a paragraph then moves the caret. When the draft equals the file the article gets its original server HTML back byte for byte; after Save `router.refresh()` swaps in the real render. Undo, Redo, Cancel or a restored draft close an open block (its range no longer describes the text). Titles, descriptions, and on a note page the creator's name and bio (`Creator` takes `devKey` — `author` or `artist` — from the note page only; a studio page renders the same block from a section document and must not mark it) are edited where they render as plain text and travel with the page draft (`CREATOR_PAGE_KEYS`). A fact table's values ("One-liner", "Aired") are edited in their cells, in either language's container, and written back into the row (`findFactRow()`/`replaceFactValue()`) — only when the value carries no Markdown of its own; a value with a link opens the block editor instead. A cell being typed into is left alone by the live repaint until it blurs. Generated lists, counts, external players and other notes' rows are read-only.
- **A draft survives anything short of Obsidian editing the same file.** Soft navigation keeps it in memory with its undo history; a reload restores it from `sessionStorage` (written a beat after the last keystroke, without history) when both revisions still match, and otherwise discards it and says so. There is no "leave this page?" prompt any more — the draft is where you left it when you come back.
- **An attached image is Obsidian's paste, done by the sidecar.** Paste, drop or pick an image while the body editor is open and `/attach-asset` writes it to `vault/<Section>/attachments/` (a cover: the note folder's `covers/` when one exists, else beside the note), mirrors it to `public/vault-assets/` so the running dev server shows it, and inserts `![[name]]` at the caret (a cover patches `cover:` under the note's revision). Format is sniffed from the bytes (JPEG, PNG, GIF, WebP, AVIF only; ≤10 MiB), the name is slugified and made vault-unique because embeds and `cover:` resolve by basename, and every step undoes the earlier ones on failure. **The image manifest is not updated** — `lib/blur.ts` reads it once per process; the new file has no blur/srcset until the next `npm run dev` or build. `getAssetIndex()` (which decides where a basename resolves) caches for only two seconds in development for this reason.
- **Saves are revision-checked and paired.** SHA-256 revisions of both files are checked before staging and again before replacement; frontmatter scalars are patched without reserialising unrelated YAML (comments, order, line endings, BOMs preserved); writes go through uniquely named siblings, fsync, atomic rename, with backups so a failed second replacement restores the first. A conflict keeps the browser draft and requires an explicit reload.
- **Keep the production audit clean**: no editor rewrite, route, token header, endpoint string or client implementation in the built JS, and no `+`, Page options or checkboxes in static HTML. Guarding a dynamic `import()` with `NODE_ENV` does NOT keep the client island out of the bundle — the webpack aliases do.
- Contextual writes refuse while the main editor has a dirty draft or a save in flight.

## What the dock does

Collapsed: a bottom-right pencil, nothing else. It is **the reading pill's twin** — `.dev-dock-bar` takes `.time-left`'s fill, ring, radius and blur, and its box is that pill's height (`--corner-pill-h`, spelled as the arithmetic behind it so the two cannot drift), because the two share that corner at different moments and should read as one object. It carries no `title`: a native tooltip is a grey box under the pointer, which is the one thing this dock does not draw, and `aria-label` names it either way. A post's time-left pill steps `--corner-pill-h` to the left of it, and rides above the bar while the bar is open, so the two never meet. Expanded (`data-dev-tools` on `<html>`): ONE bar fixed under the page, one row: a `?` whose hover text is the how-to, the editing tools (enabled while a block or the source is open, Done/close among them), the **Page options** toggle (when the page has options), the language and word count while editing, then the page's controls — a link to the same route on `siteUrl`, an `obsidian://open` link for the active language's file, the translation button, Undo/Redo, language switch, Cancel/Save with one shared history across every page field — and the close pencil at the far right, the full width of the window and never wrapping (a window too narrow scrolls the row sideways; the status line gives way first). Page options open as a compact panel above the row (three columns from 40rem); Source and Page options are one-at-a-time — opening either closes the other. **Messages are toasts** at the bar's right end, above it (`.dev-toast`): loading, saved, conflict with Reload, unavailable with Retry, no source, and the rest; each problem carries what to do about it on hover (`editorHelp`) and stays until dismissed with its ×, while good news (saved, attached, translation created, draft restored) leaves on its own after four seconds. The row itself is centred. The options form is still rendered by the entry page's server slot (`DevEntryOptionsSlot`, which knows the note) and portals itself into the bar's `[data-dev-options-mount]`; the bar shows the toggle once something has arrived there. Drafts survive soft navigation (kept with both revisions), prompt before same-origin navigation and on reload, and are hidden but retained when the dock closes. Cmd/Ctrl+S goes through `shortcutKey()`.

Two more dock buttons appear when they apply: **Create the Ukrainian body** on a note with no `.uk.md` sibling (`/create-translation` writes a copy of the English Markdown, body only, so the translation is done in place; disabled while a draft is dirty) and **Insert an image** while a body editor is open (a file picker feeding the attach flow above).

The tools bar (`.dev-editor-drawer[data-mode]`, fixed under the page whenever the dock is open on a page with a body; its height is measured into `--dev-bar-h` for the page's padding and the dock's lift). **It is the reading pill's material**, like the corner pencil: `--chrome-bg` behind a 12px blur, with the top hairline (`--chrome-ring`) standing in for the pill's ring, since a full inset ring on something pinned to three window edges would only draw lines along them. Its tools: Bold (Cmd/Ctrl+B), Italic (Cmd/Ctrl+I), strikethrough, inline code, `[[ ]]` link (Cmd/Ctrl+K, opens the suggestion list), H2, H3, quote, list, numbered list, task list, footnote (numbered after the last definition in the whole note; the note goes at the end of the block), a callout picker with every kind the stylesheet knows plus `spoiler` and `pull`, code fence, table, divider, player (an Apple Music or YouTube link on its own line), image — each wraps or unwraps the selection or prefixes the touched lines, with a selected placeholder where there was only a caret — then ¶+ (new paragraph), Source, a status line (language, word count via `wordCount()` in `lib/plural.ts`, live preview on/off; a hint while nothing is open) and Done/close. Every tool carries a hover description in `data-tip`, **but the bar does not draw it** (`.dev-editor-drawer [data-tip]:hover::after { content: none }`): a plate appearing under the pointer is the grey wash this dock is built without, and `.dev-bar-row` clips its own overflow, so a tool on the top row swallowed its box while one on a wrapped second row painted it over the row above — the same control answering a hover two different ways. `aria-label` names every tool. The pseudo-element still serves the toast, which floats clear of the bar (`data-tip-align="end"` there). In source mode the bar grows to `--dev-drawer-h` with a drag (or ArrowUp/Down) handle remembered in `localStorage`. Escape closes the block or the source, keeping the draft; a second Escape closes the dock. Contextual writes (cover, options, create) refuse while a block is open, since their `router.refresh()` would re-render the article under it. The textarea also knows Obsidian's habits: `[[` opens a suggestion list of page titles from `/search-index.json` (either language; arrows, Enter/Tab, Escape; a `|` label or `]]` closes it), Tab indents (Shift+Tab outdents; a selection moves whole lines), and an image pasted or dropped on it is attached. The pure parts are `indentLines()`, `wikiLinkQuery()`, `completeWikiLink()`, `wikiLinkMatches()`, `wrapSelection()`, `toggleLinePrefix()`, `countWords()`, `sourcePositionFor()` in `lib/dev-tools.ts`.

Contextual controls while expanded:

- **`+` beside a section title** (Posts, Music, People, Shelf, Projects): creates an EN/UK Draft pair from the section's server-read `type:`; bilingual title and description required; Shelf picks the medium folder; Music records artist, format, ENG/UA/RU shelf, optional genres and player URL. Rejects unsafe filenames and filename/route-slug collisions; creates the pair with rollback. "New # type" means a new category value, not a new section renderer.
- **Section options on /music** (`DevSectionOptionsSlot` → `DevSectionOptions`, same mount): the Apple Music **playlists** (one link per line, written as `playlists:` — a list, or removed when empty) and each **artist's** Ukrainian name and bios from the section's `artists:` list, patched one artist at a time inside the YAML block sequence (`patchArtistItem()`: found by `name:`, fields replaced on their own lines including `>-` block scalars, comments and `photo:` untouched) through `/save-music-section`. A note's own `artist_bio:` stays on the note. Aliased out of production in `next.config.ts` like the other slots.
- **Page options (in the bar, on entry pages)**: Title and description in both languages (the same fields the header edits inline; a save here tells the dock to re-read the page — `reload` on the saved event — so its baseline and markers follow), Draft (reads `published: false` too, writes `draft: true`), Date (with a Today button; written unquoted so it stays a YAML date), **More fields** (aliases and URL slug on every note; maturity on posts; medium, creator and Ukrainian name, creator bios, IMDb id on films and shows, video link and publish date on videos; artist and Ukrainian name, record bios, format, shelf language and genres on music — each validated by the sidecar, whose message is shown when a value is refused), **Delete this note** (moves the `.md` and `.uk.md` pair to `vault/.trash/`, which the site, the sync and git ignore — reversible from Obsidian; confirmed first; lands on the section page), categories (existing or new; a new one is valid at once and falls back to its English label until `lib/categories.ts` has a translation), Post series (`series`, one vault-wide `series_uk`, `part`), Shelf status (finished / in progress / queued, spelt with the medium's verb — `reading`, `watching`, `playing` — and an unfamiliar existing word is kept as its own option rather than rewritten) and rating (half stars), and a Cover picker on shelf, people and music notes (the attach flow with `purpose: "cover"`; shows the current file name). Changes are compared against RAW YAML keys.
- **Top-list rows** (movies, shows, games): stars become a half-star slider (arrows, Home/End, Delete clears) and rows drag into a manual order that writes consecutive `top_order:` across the participating notes; navigation is suppressed only past the drag threshold.
- **Now goals**: rendered boxes become checkboxes that flip one `[ ]`/`[x]` marker in `main.md` and `main.uk.md` together, guarded by the rendered English label.

Endpoints: `/page-document`, `/save-page`, `/document`, `/save`, `/create-entry`, `/toggle-now-goal`, `/reorder`, `/create-translation`, `/attach-asset`, `/preview` (read-only), `/delete-entry`. `EDITOR_PROTOCOL` is 3. Tests: `lib/dev-tools.test.ts`, `scripts/dev-editor-core.test.mjs`, `scripts/dev-editor-server.test.mjs`.
