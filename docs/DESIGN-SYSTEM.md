# Design system and `globals.css`

Read this before writing any CSS or any new UI. Tokens and the page shell are
summarised in `docs/ARCHITECTURE.md → Design system`; this file is the rules
that are not visible from the tokens themselves. Reasons: `docs/DECISIONS.md`
#51, #52, #55, #58, #59, #60, #61, #64, #81, #104, #107.

## Rules for any new UI

- **Never re-type a page container.** `components/Page.tsx` owns measure, gutters and rhythm (`--measure`, `--gutter`, `--page-y`). It used to be `max-w-2xl px-6 py-14 lg:py-24` copy-pasted into seven route files, two of which had already drifted (#58).
- **Use the tokens, don't type literals** (#58). Radius `--r-xs|sm|md|lg|xl|full` (4/6/8/12/16px + pill, equal to Tailwind's scale so the two can't drift). Motion `--ease` + `--dur-fast|--dur|--dur-slow` (120/200/320ms; Tailwind's `--default-transition-*` point at them, so utility classes move the same way). Surfaces: `--surface` is a card/cover/badge FILL, `--bg-hover` is the pointer response, `--chrome-bg`/`--chrome-ring` are the floating bars and pills (built from `--surface` in dark mode — a pill made of `--bg` is invisible on a dark page, #60).
- **Any new UI must work in both languages, light and dark, both colour families, and under `prefers-reduced-motion`.** Using the tokens is what makes that nearly free. Check the result in both languages, light and dark, with Vaultsite and Notion colours before calling it done.
- Give clickable things `press` (`press press-soft` for cards), and don't add `transition-colors` beside `.press` — it declares its own.
- Dark mode is `prefers-color-scheme` only — no manual light/dark toggle. Cmd+K changes the independent colour family (`data-colour-theme="notion"`); Vaultsite is the default. Both families must define light and dark values for every colour token (#175).
- Icons (`components/icons.tsx`) are **rendered in the sidebar only** — no icons on page content (#64), with ONE exception, added at the owner's request: `SearchIcon` on the 404's Search button (`components/NotFoundSearch.tsx`, #161), where two identical grey buttons sit side by side and the mark is what tells them apart before the words are read. It is the counterpart of the arrow on Home. **There is now a SECOND, also asked for directly** (#182): `HeadphonesIcon` (a filled `PlayIcon` until #195) before "Listen" in a note's metadata line (`components/ReadAloud.tsx`) — the one control on a page that starts sound, marked as such before the word is read. And a THIRD, again asked for directly (#193): `ListIcon` before the series badge ("1 of 2"), replacing its dotted underline. The floating read-aloud player's play/pause/close glyphs are chrome, not page content. Every further exception should be the owner's explicit request, as these three were. `resolveIcon()` maps vault frontmatter emoji/names → SVGs; unknown emoji render as text.

## Editing `globals.css`

- It has no `@layer`, so position is the tie-breaker — an override belongs BELOW what it overrides. This has caused four separate bugs (#51, #52, #55, #81), the subtlest being a `transition:` shorthand hundreds of lines above silently resetting a later `transform`.
- **A bare class selector here also beats a Tailwind utility of the same specificity**, so never set `position`, `display` or `width` on a class whose element carries a utility for it — `.chrome-bar { position: relative }` once overrode `fixed` and dropped the floating breadcrumb into the page flow at full width (#81). The fixed position now belongs to `.chrome-cluster`; each capsule owns its relative containing block (#162).
- The element carrying `.lang-en`/`.lang-uk` must NEVER be given a `display` — the language toggle hides the inactive one with `display: none`, and a bare rule at the foot of the file wins on position and paints both languages at once (it did, on the book spines — #110). Put the `display` on an inner element.
- **The design itself** lives in one block at the FOOT of `globals.css` (#59): Source Serif 4 for everything except code (sidebar and `svg.diagram text` included), big fluid `.page-title`, wide tonal range, dark mode with real elevation (`--surface` above `--bg`), demoted `.entry-meta`/`.entry-tags`, generous space above `h2`. The old complete-design switch and its losing design are deleted; the colour-only switch in #175 sits entirely in the tokens and must not fork these component rules.
- **`.press`** (#55) dips a control to 97% while held; `.press-soft` (99%) for cards. Opt-in — a scaled inline prose link reads as a rendering fault. Named components join by selector at the very END of `globals.css`; don't move that block up. `.press:active` declares `transform` OUTRIGHT, so a component that composes its own transform (`.lightbox-arrow`, `.selection-pill`, `.book-spine`) has to restate the whole transform rather than set a variable.
- **Colour is a mark, not a surface** (#215). Four tokens, `--hue-blue` (callouts only; "New" moved to `--hue-star`), `--hue-green` (done), `--hue-amber` (under way), `--hue-red` (danger), plus `--hue-star`, a desaturated amber for ratings. Use one only for a small thing that states a kind or a state: a tick, a dot, a star, a callout's label. Category colours, a coloured reading bar and a coloured arrow ring were tried and rejected. Never a background, border, heading or link colour. On a large element tint it (`color-mix` at 10 to 15%) instead of filling.
- **`.lift`** (#213) is what a picture does under the pointer: it rises 3px on a spring with a longer shadow, and is pushed back down while held. Never a hover zoom. Put `lift` on the picture's frame inside a `group` link; it uses `translate`, so it composes with `.press`. A row of lifting cards inside a horizontal scroller needs `pt-2` of headroom or the lift is clipped.
- **Everything that floats over the page is ONE material** — the breadcrumb bar's `--chrome-bg` fill and `--chrome-ring` hairline, blurred (#185, #186). Pills wear `.chrome-bar` (list below). Panels — the drawer itself (#187, #188), the contents sheet (#189), the series list and link previews (#190) — all take the drawer's recipe: `--r-xl`, the inset hairline with no border, its drop shadow and the bar's two blur layers (a panel that scrolls does so in an inner `…-body` box, or the layers scroll away). The ⌘K and shortcut dialogs keep the fill and hairline with ONE even 14px blur. The page itself (its chips, buttons, cards and badges) keeps its own look: #185 carried the material into it and was taken back. The overlay block is the LAST in `globals.css`. Left out on purpose: the frameless phone music sheet (#94) and the lightbox's round arrows.
- **Every floating chip wears `.chrome-bar` itself** — the breadcrumb bar, the Today's vibe capsule, the time remaining (`.time-left`), "Continue" (`.resume-reading`), the read-aloud player, the contents button, the phone's album button (square, for its art), the selection link, the skip link and the dev pencil — at its 2.5rem height, its 14px medium `--text-secondary` type, 0.75rem off the window's edge and its z-index 30 (#167, #184). A new chip takes the class; it does not copy the fill, ring and blur, which is how the bottom ones drifted to 34px, 13px and a flat blur.
- `.chrome-bar` and `.toc-bar` share a LAYERED blur — two masked pseudo-elements instead of a `backdrop-blur-*` utility — so their edges dissolve rather than ending at a hard rim. Their `z-index: -1` layers rely on each pill's own `z-index` for its stacking context — **never add `isolation: isolate`**, which forms a backdrop root and stops `backdrop-filter` sampling anything behind the element (#81). `.sidebar-panel` deliberately takes ONE even blur on the element itself: graduating it across 224px is wide enough to see as a seam down the middle.
- **The drawer floats** (#187): 0.75rem off the top, bottom and left, `--r-xl`, the inset `--chrome-ring` all the way round plus a drop shadow, still `w-56` (the constellation's strip is measured against it) and still ONE even blur. The insets live on `.sidebar-panel` in the overlay block; `fixed` stays a utility in Chrome.tsx. Closed, it parks its own width PLUS 3rem off-screen, so neither the hairline nor the shadow's reach shows at the window's edge — an outset line used to leave a 1px stripe down the left of every page (#74, #80). The modal backdrop covers the WHOLE viewport, panel included — two attempts to stop it at the panel's edge both produced a doubled edge (#74, #80, #81).
- Any `animation-timeline` declaration must sit inside `@supports`, or it falls back to the default TIME timeline and just plays once on load. Never put a scroll-driven animation on a property an element already transitions — the animation wins and the transition silently stops working (#81).
- A keyframe that names only `from` with `animation-fill-mode: both` ends on the element's OWN computed value — `wash-in` and `nav-tree-in` both rely on this. **Never add a `to:`** to either; it would flatten dark mode to the light value, or freeze one list's cap into the other's (#92, #124).
- `.stagger > *` carries `animation: item-in … both`, and an animation that fills forever on `opacity`/`transform` gives every child a PERMANENT stacking context — nothing inside one can outrank a later sibling. Put a z-index on the slot, not on what is inside it (#110).

- **`app/page-ideas.css`** holds the design ideas switched in `pageIdeas` (`lib/site-config.ts`, #179). Every selector there must name an `.idea-` class (`scripts/page-ideas.test.mjs`), so a switch turned off leaves the page exactly as it was. When an idea is kept for good, move its rules into `globals.css` and delete its switch.

## Breakpoints

- **The gutters arrive at 1168px**, not Tailwind's `xl` — the contents rail, sidenotes, pull-quotes, `.resume-reading`'s move under the rail, and the shelf note's gutter column all share that one query. It is DERIVED (39rem measure → 19.5rem half + 2.5rem gap + 13rem rail + 1.5rem margin = 73rem), so re-derive it if `--measure` or the rail's width changes rather than nudging it, and move all the queries together or the page goes lopsided (#107, #136).
- The music note's gutter PLAYER keeps 1400px — it takes 21rem + 20rem of LAYOUT past centre, since a transform shrinks paint and not layout (#99).
- 640px is the phone line (drawer tree, people cards, music pill, lightbox arrows, time-left chip); 480px is where the fact list runs on and the shelf card height steps down.

## Colour: monochrome, and the exceptions

Design is monochrome: no blue accent in hovers/active states. **There is no `--accent` token** — deleted after four passes trying to find the right amount of one colour (#64). State chips, the ToC marker, `[progress::]` and reading bars, focus rings, the selection wash and action links all use `--text`: on a page with no other colour, full text colour IS the emphasis. Callouts keep their four hues (there colour carries meaning). Active chips/nav use text-on-bg inversion.

The two families change the NEUTRALS, not that rule. Vaultsite is the cooler, higher-contrast default. Notion uses its warmer current semantic neutrals for the same roles, selected by `html[data-colour-theme="notion"]`; it does not import Notion's blue interaction accent, typography or component styling. The choice lives in localStorage under `colour-theme`, is restored before paint by `app/layout.tsx`, and is changed only by the Cmd+K action (`components/useColourTheme.ts`, #175).

The exceptions, all of them named:

- ONE hover-only exception (#56): the four platform icons take their brand colour (`.social-link[data-social]`, `--brand`, with near-white stand-ins for GitHub/X in dark mode; mail has no platform, so it keeps `var(--text)`). **There were TWO** — people photos sat at `grayscale(0.3)` (`.person-photo`) and returned to full colour on hover — and that half was removed at the owner's request (#125). The class is GONE. Don't reintroduce it, here or anywhere: every portrait on the site is now full colour at rest.
- The sidebar's flag-coloured line on Ukrainian CELEBRATION days (`--ua-blue`/`--ua-yellow`, #104) — one line, eight days a year, never an accent; the seven remembrance days stay monochrome on purpose. See `docs/CHROME.md`.
- **There is now a SECOND use of those tokens, and it is permanent**: the /music language button paints its label in the same gradient while **`RU`** is the selected step (#117). That was asked for directly and stretches #104 by exactly one exception — a third use would end the rule, so rewrite it rather than erode it again.
- A book spine's colour is computed per book from its own cover and does not flip with the theme; nothing there is the site's colour (#110).
- Draft's green outline chip is a dev-only warning, not a published colour.

## Typeface

- **One typeface — Source Serif 4, everything except code**, self-hosted via `next/font` with the `cyrillic` subset AND `axes: ["opsz"]` (#61). Script coverage is a hard filter applied before a typeface is judged on looks: every note has a Ukrainian translation, and Newsreader was chosen and dropped for exactly this (#59). Quotes are the same family in italic — don't reach for a second family, that's what Lora was and it had to go.
- The build-time `next/og` renderer cannot read that CSS font registration, so `assets/fonts/` carries static regular and bold TTFs of the same family for shared-link cards only (#106).

## Verifying CSS

- **Verifying a Tailwind class actually shipped**: grep the built CSS for the ESCAPED form (`.w-\[calc\(…\)\]`), or read the element's computed style. A plain grep finds nothing whether or not the rule exists, and "nothing" looks exactly like "never emitted" (#54).
- Under `preserve-3d` a parent is a sibling plane, not a container — ask `elementFromPoint` what is really under the cursor before debugging the code that runs after the event. **A hit-testing fix verified in one engine is verified in one engine**: run anything that depends on hit-testing a 3D-transformed element in WebKit before believing it (#123).
- When an image looks broken, check the server and the lazy state before the markup (#104).

- **Two things wearing `.chrome-bar` must sit at the same `z-index`, or they
  will not look the same.** The vibe capsule at `z-index: 0` and the breadcrumb
  chip at `z-30` carry an identical `inset 0 0 0 1px var(--chrome-ring)`, and
  the capsule's came out a bright white outline next to the chip's soft grey
  hairline — the inset ring composites differently over the blur pseudo-elements
  depending on the stacking level. A non-auto z-index is needed at all so those
  `z-index: -1` pseudo-elements stay inside the box; it has to be *the same*
  non-auto value to match (#167).
- **The Today’s vibe exception is gone (#165).** #163's capsule wore
  component-scoped marigold paper/dark ink; the owner asked for it to fit the
  site instead, so it now wears `.chrome-bar`'s own material at the breadcrumb
  chip's height and carries emphasis in weight and `--text` alone. Nothing in
  the chrome is coloured any more — the one colour left in the capsule is the
  track's cover art, which is a photograph, not a token.

## Shortened text

Any element that truncates prose with `truncate` or `-webkit-line-clamp` also takes `data-tidy`, so `components/ClampTidy.tsx` can move the "…" off a comma or a space (DECISIONS #217). The element must contain only text or one `<T>`.

## Note skins

A note with `skin:` in its frontmatter is outside every rule in this file, by the owner's request (#234): its own colours, a second typeface, full-bleed layout, motion. Today there is one, `monster`, on `vault/Posts/Monster Energy.md`.

- The skin's CSS is `public/skins/<name>.css`: plain CSS, served as written, linked only by the skinned page (`components/NoteSkin.tsx`). It is not imported, and Tailwind and PostCSS never see it.
- **Every selector there names `[data-skin="<name>"]`** and no keyframe reuses a site name (`scripts/skins.test.mjs`). Restyle the site's chrome by re-pointing tokens under `html:has(.page[data-skin="<name>"])`, never by reaching into `Chrome`.
- **The Monster skin is a dark room, and nothing in it meets anything else along a hard line.** The page is black throughout; a screen, a picture or a word is something lit that falls off into the dark. A new block does the same. Flat colour to the window's edge, a shaped divider between two fields, and a bright rim on glowing type were all built first and taken out at the owner's request.
- Inside a plate (`.mx-plate`) the site's text tokens are re-pointed at that plate's ink. Without that, any site rule that paints with `--text` draws white on a white screen.
- In the note, plates are raw `<section class="mx-plate">` tags (`mx-screen mx-red` or `mx-screen mx-white` for a lit screen, `mx-end` for sources) with a blank line after the opening tag and before the closing one, so the Markdown between them is still parsed. A picture directly followed by a `##` or a `>` takes that block in: the words are set into the photograph by the driver. The band of picture drawn back over the words' feet is measured in the TYPE's size (`--mx-foot`, `--mx-type`), not the picture's height, or on a phone it covers the whole last line; the credit sits above the last 11% of the frame, where the picture dissolves.
- Pictures are graded by hand with `node scripts/skin-grade.mjs in.jpg out-bw.jpg --look bw|red` before they enter the vault; `--red 0..1` sets how far a picture goes from black and white toward red (the truck is at 0.6, the MotoGP picture at 0.5, both at the owner's eye). The file name ends in `-bw` or `-red`, and that suffix is what the skin reads to choose the ink of the words it sets into the picture: red on `-bw`, white on `-red`. `--key white` writes a cut-out with an alpha channel, which is what `skin_art:` wants.
- **Speed is measured, and five things are not allowed** (#234 has the numbers): an entrance that fills `both` or `forwards` (it keeps its element a compositor layer after it has played; every revealed paragraph and word did, 134 layers, and a 5K screen froze where a laptop did not; fill `backwards`, `scripts/skins.test.mjs` checks); a blurred `text-shadow` on display type (it alone took the page to 12 frames a second; echo the word unblurred and put a gradient behind it instead); a custom property written per frame from script; a `filter` or anything but a transform or opacity driven by the scroll; a big blurred `box-shadow` or `drop-shadow` where a gradient will do. Check a change with a real scroll gesture in a visible or headless browser, AND count the compositor's layers at a 2560×1440 window at two pixels a point (`LayerTree.enable` over CDP): a headless frame count stays at 60 on a page a real 5K screen cannot hold. About 30 drawing layers is what the page has now. The app's preview pane throttles its timeline while hidden and proves nothing about smoothness.
- **The hero is drawn once and then only moved, and an element has one animation** (`scripts/skins.test.mjs`). Two animations that set the same property on one element (two transforms, two opacities) are both taken off the compositor: the title's entrance ran on the main thread beside its flicker, and the title was drawn again from scratch at every size it passed through. A second movement goes on an element inside or outside the first: the flicker is on `.note-header-text`, the opening's word lands on a `<span>` inside the `<b>` that is pulled out. A shadow, mask or blend goes on a box that stands still INSIDE the one that moves (`.mx-lit` in `.mx-stand`), and a fading parent holds one layer, not two (the smoke's corners are in its shader; in a landscape window the block round the title fills the header so the date line is placed inside it). Check with a trace, not by eye: `blink.animations` gives each animation's `compositeFailed`, and `viz` gives `DirectRenderer::DrawRenderPass` per frame (two on the hero now: the page and the site's bar).
- **Nothing in the hero makes an entrance, and no skin uses an SVG filter** (`scripts/skins.test.mjs`). The title, the can and the date line are standing there when the opening lifts; only the scroll moves them. The title slammed in after the can and wore `filter: url(#…)`: the owner saw a can with no words, then the words stretched and dim, each held for a moment. The title carries the headlines' unblurred ghost (`--mx-ghost`) instead.
- Hide a not-yet-revealed element with `opacity`, never a zero-area `clip-path`: clipped away it never intersects the viewport, so it is never revealed and its lazy image never loads.
- Motion hangs off `data-mx="live"`, which the driver sets only when it runs without reduced motion. Anything hidden until revealed is scoped to that attribute and carries `.mx-hold`, which the driver gives only to what is still BELOW the window when it starts, and takes back from a little below the window (the observer's `rootMargin` is +12%, threshold 0; waiting until a thing was inside the window left a screen of nothing whenever the observer reported late): the chunk can arrive late, or the page open part-way down, and what is already on screen must not blink out to make an entrance.
- The words' drift inside a picture (`mx-drift`) is the one thing in the body the scroll drives, and it is off in a large window on a dense screen: a moving heading makes layers of itself, of what is drawn over it and of the figure's mask, about 170 MB a picture at 5K. The smoke draws thirty times a second by the clock, because each frame of it has the whole hero composited again.
- A picture's `sizes` is set by the driver from the picture's own box (a `ResizeObserver`, so the language that was hidden at load is sized when it is shown). The can's `sizes` is the stand's real width, written from the same numbers as `.mx-stand`, and the mask that cuts its light to its outline is named by the driver from the file the browser chose (`--mx-art`); change the stand's size in the stylesheet and `artSizes()` in the driver together.
- A new skin is a name in `SKINS` (`lib/skins.ts`), a stylesheet and a branch in `NoteSkin`. Do not add one unasked, and do not carry a skin's look into the site.
