# CLAUDE.md — AI assistant context

Context file for AI models working on this repo. Read this first, then `docs/ARCHITECTURE.md`.

## What this is

Kyrylo's portfolio site, published from an Obsidian vault. The `vault/` folder IS the CMS: TOP-LEVEL folders → section pages, `.md` files inside them → entries with their own URLs. Pipeline: Obsidian Git → GitHub → Vercel auto-deploy. Fully static (SSG), no database, no runtime fs access.

Sections may hold subfolders (`vault/Shelf/Books/`, `vault/Shelf/Books/covers/`, `vault/Posts/attachments/`) — they're filing, for the owner's benefit in Obsidian. A subfolder never becomes a page and never appears in a URL: an entry's slug comes from its file name, so a note can move between folders without breaking its address.

## Hard rules

1. **Never make content edits outside `vault/`** unless asked — content belongs to the owner via Obsidian.
2. **Keep the site fully static.** No runtime fs reads, no server actions for content. Everything resolves at build time via `generateStaticParams`.
3. **Keep `vault/` conventions stable** (top-level folder + `main.md` = section; other `.md` = entries, at any depth inside it). Breaking these breaks the owner's Obsidian workflow.
4. **Update `docs/DECISIONS.md`** when you make a non-obvious architectural choice.
5. Assets: never reference vault files directly from components — they're mirrored to `public/vault-assets/` by `scripts/sync-assets.mjs` (runs via predev/prebuild).

The exception to “no runtime fs access” is deliberately outside the deployed
application: `npm run dev` supervises Next plus a loopback-only authoring
sidecar. Production builds and `next start` never start it and have no editor
rewrite. See “Local authoring dock” below and DECISIONS #118.
6. **Two agents work here.** Keep `CLAUDE.md` and `AGENTS.md` in step, and never leave the tree half-edited — see below.

## Two agents work on this repo

Claude Code and Codex are both used here, on the same checkout. Each auto-loads its own file:

| File | Loaded by | Role |
|---|---|---|
| `CLAUDE.md` | Claude Code | The full reference. Owns feature detail and conventions. |
| `AGENTS.md` | Codex | A thin always-loaded map that defers here for detail. |
| `docs/` | both | Shared and authoritative — `ARCHITECTURE.md`, `DECISIONS.md`, the workflows. |

- **Code and `docs/DECISIONS.md` are the source of truth.** Where prose disagrees with the code, the code wins — say so rather than "fixing" the code to match a stale sentence.
- **Change a convention, command, or invariant → update BOTH agent files in the same change**, plus `docs/DECISIONS.md` if the choice is non-obvious. These two files have already drifted apart once (each described a different `npm test` wiring), which is exactly the failure this rule prevents.
- **`AGENTS.md` must not restate feature detail** that this file owns — it should point here instead. Duplicated prose is what drifts.
- **One agent at a time in this working tree.** Obsidian Git auto-commits *everything* (`autoCommitOnlyStaged: false`) every 10 minutes and pushes, and Vercel deploys the result — so a half-finished edit publishes itself on a timer. Finish and verify a change, or work in a separate `git worktree`. Don't run Claude and Codex against this checkout simultaneously.
- **Check `git status --short` before editing.** Uncommitted changes you don't recognise may be the other agent's or the owner's in-flight work: leave them alone and ask. Never `git restore`, `git checkout --`, or `git stash` a file you didn't change yourself.

## Conventions

- Home is the section whose slug is `home` (`app/page.tsx`); `lib/section-types.tsx` is the registry mapping a section `type` to its list component. A section's `main.md` PROSE is normally printed by `app/[section]/page.tsx` above the list; a type listed in `bodyBelow` there (music only) receives it as the `body` prop and places it itself — the page still renders the markdown and hands down ONE node, so the `.lang-en`/`.lang-uk` pair is never split. `docs/DECISIONS.md` #111.
- Icons (`components/icons.tsx`) are **rendered in the sidebar only** — no icons on page content (#64). `resolveIcon()` maps vault frontmatter emoji/names → SVGs; unknown emoji render as text.
- Frontmatter (section `main.md`): `title`, `icon`, `order`, `description`, `type`, `slug` (override), `draft`. Full frontmatter is exposed as `section.meta` so section types can define their own keys (e.g. `music` reads `playlists:`).
- Section types: `posts` (default; category filter chips from entry `category:` frontmatter — chips are links to `/posts?category=X`, read by `useSearchParams()` in `PostListClient`, so a post's own category chip lands here pre-filtered. Unlike the shelf these are NOT separate pages: no per-category title/OG/sitemap entry, and filtering needs JS), `music` (Apple Music iframe embeds — `lib/apple-music.ts`, no API key. The section's notes are GROUPED BY ARTIST (`lib/music.ts`): one card each, ordered by whichever artist has the newest note, tinted by that artist's most recent cover, opening with a portrait + name + short description and listing that artist's notes under it. **Two different biographies, deliberately**: `artists:` in the section's `main.md` (`name`/`name_uk`/`photo`/`bio`/`bio_uk`) describes the ARTIST and drives the card; a note's own `artist_bio:` describes THAT RECORD and drives the block on the note page — don't let one become a copy of the other. Artists live in section frontmatter rather than as files because any `.md` under the folder would become an entry with its own URL. A note's `format:` (`album|track|single|ep|mixtape|live|compilation`) prints in grey after its title (`Clancy · Album`) and is INFERRED when absent — a link with a track id is a Track, anything else an Album — so only an EP or a single needs writing down. A note naming no artist joins one trailing card-less group; a note naming an unknown artist still gets a card, just no portrait or bio. The portrait is 5rem and rises 23px through the card's TOP edge — which is why `.music-card` is `overflow: visible` and `.music-wash` carries `border-radius: inherit` instead; it is positioned ABSOLUTELY, because as a flex child a negative margin drags the name and bio with it. - Frontmatter (entries): `title`, `date` (YYYY-MM-DD), `description`, `slug`, `draft` (or `published: false`), `series` (+ optional `series_uk`, `part`), `cover:` (people, shelf and music), `imdb_id:`/`imdb:` (shelf movies and shows — see Common tasks). `description_uk:` is written in notes but is NOT on `Entry` — only the music list reads it, out of `entry.meta`.
- Sized image embeds ≤128px (e.g. `![[me.jpeg|93]]`) render as circular avatars (`.avatar` class); larger sizes keep the rounded-rectangle style.
- The `posts` list groups entries by year (empty years never render); row dates are DD.MM. This date treatment is posts-only — other types show full dates.
- The `projects` list truncates entries over 1000 markdown chars; "Continue reading" links to the entry's own page.
- Breadcrumb names the current page's ANCESTORS, not itself ("Kyrylo · Posts" on a post) — the page's own title is already its `<h1>`. Each part is clickable. On home, and on a section's own page, only the site name remains. The section is the only ancestor at any depth: a shelf medium and its category pages all read "Kyrylo · Shelf", since they're one page with a different chip pressed and naming the medium both repeated the `<h1>` and changed the trail's shape as you filtered (#65).
- Slugs: `slugify()` in `lib/vault.ts` — keep stable, changing it breaks URLs.
- Styling: Tailwind utility classes + CSS variables in `app/globals.css`. Markdown output is styled by the hand-written `.prose` classes there. Dark mode is `prefers-color-scheme` only — no manual toggle. See the Design system section below before writing any CSS.

## Design system

Full reference: `docs/ARCHITECTURE.md` → Design system. The short version:

- **Never re-type a page container.** `components/Page.tsx` owns measure, gutters and rhythm (`--measure`, `--gutter`, `--page-y`). It used to be `max-w-2xl px-6 py-14 lg:py-24` copy-pasted into seven route files, two of which had already drifted (`docs/DECISIONS.md` #58).
- **Use the tokens, don't type literals** (#58). Radius `--r-xs|sm|md|lg|xl|full` (4/6/8/12/16px + pill, equal to Tailwind's scale so the two can't drift). Motion `--ease` + `--dur-fast|--dur|--dur-slow` (120/200/320ms; Tailwind's `--default-transition-*` point at them, so utility classes move the same way). Surfaces: `--surface` is a card/cover/badge FILL, `--bg-hover` is the pointer response, `--chrome-bg`/`--chrome-ring` are the floating bars and pills (built from `--surface` in dark mode — a pill made of `--bg` is invisible on a dark page, `docs/DECISIONS.md` #60). `.chrome-bar` and `.toc-bar` share a LAYERED blur — two masked pseudo-elements instead of a `backdrop-blur-*` utility — so their edges dissolve rather than ending at a hard rim. Their `z-index: -1` layers rely on each pill's own `z-index` for its stacking context — **never add `isolation: isolate`**, which forms a backdrop root and stops `backdrop-filter` sampling anything behind the element (#81). `.sidebar-panel` deliberately takes ONE even blur on the element itself: graduating it across 224px is wide enough to see as a seam down the middle, so the panel reads as two panels side by side rather than one dissolving edge — graduation is for surfaces small enough that their edges are most of them. The drawer's hairline must stay an INSET `box-shadow`: an outset one leaves a 1px line down the left of the window whenever the panel is parked off-screen, and a shadow rather than a border costs no layout — the constellation's strip is measured against the full `w-56`. The modal backdrop covers the WHOLE viewport, panel included — two attempts to stop it at the panel's edge (a static `left-56`, then a transform tracking the slide) both produced a doubled edge: the page reads bright through the translucent panel and dark beside it, so the sidebar looks like a window cut out of the page. A translucent panel over a dimmed page is meant to be darker. The tell was that it only showed when opening by the icon, never by the edge peek — which has no backdrop (#74, #80).
- **The gutters arrive at 1168px**, not Tailwind's `xl` — the contents rail, sidenotes, pull-quotes and `.resume-reading`'s move under the rail all share that one query. It is DERIVED (39rem measure → 19.5rem half + 2.5rem gap + 13rem rail + 1.5rem margin = 73rem), so re-derive it if `--measure` or the rail's width changes rather than nudging it, and move all five queries together or the page goes lopsided (`docs/DECISIONS.md` #107).
- **`.press`** (#55) dips a control to 97% while held; `.press-soft` (99%) for cards. Opt-in — a scaled inline prose link reads as a rendering fault. Named components join by selector at the very END of `globals.css`; don't move that block up.
- **The design itself** lives in one block at the FOOT of `globals.css` (`docs/DECISIONS.md` #59): Source Serif 4 for everything except code (sidebar and `svg.diagram text` included), big fluid `.page-title`, wide tonal range, dark mode with real elevation (`--surface` above `--bg`), demoted `.entry-meta`/`.entry-tags`, generous space above `h2`. It shipped as one of two switchable themes while the choice was being made; the switch and the losing design are deleted.
- **Any new UI must work in both languages, light and dark, and under `prefers-reduced-motion`.** Using the tokens is what makes that nearly free.
- **One typeface — Source Serif 4, everything except code**, self-hosted via `next/font` with the `cyrillic` subset AND `axes: ["opsz"]` (#61). Script coverage is a hard filter applied before a typeface is judged on looks: every note has a Ukrainian translation, and Newsreader was chosen and dropped for exactly this (#59). Quotes are the same family in italic — don't reach for a second family, that's what Lora was and it had to go.

## Content intake (most common task)

When Kyrylo hands you raw content (a post, book/movie thoughts, a project
update), follow **`docs/CONTENT-WORKFLOW.md`** — the full playbook. Core rules:

1. Light-touch editing only — fix typos/grammar/structure, never his voice or opinions.
2. Ask follow-ups only when genuinely ambiguous (section unclear, new category, factual gap) — batch questions, use defaults otherwise.
3. Publish directly (no `draft: true` unless he asks).
4. Add cross-site wiki links (`[[Note]]`, `[[Folder/main|Label]]` for sections) — this is expected, not optional. Give new notes an `aliases:` frontmatter list (natural phrases like "CompTIA Security+"), then retro-link: find exact mentions of the new subject in existing notes and convert those phrases into wiki links (wording untouched, edits reported).
5. Source images automatically: download covers into the vault folder (batch-ask permission first; `cover: https://…` URL as fallback). Books → Open Library; people → Wikimedia Commons only, license noted. Never random image results, never AI portraits of real people.
6. Factual notes (People, current events) end with a `## Sources` section (2–4 links used for verification). Skip for opinion/shelf/music notes.
7. Translate ALL content, both languages: `title_uk:` in frontmatter AND a full professional Ukrainian body in a sibling `<name>.uk.md` (posts) / `main.uk.md` (sections), body-only, same structure/links/embeds. A note without its `.uk.md` is unfinished. See `docs/CONTENT-WORKFLOW.md → Translation`.
8. Offer a diagram when a post/project would benefit; generate it as a self-theming `.svg` (see `docs/CONTENT-WORKFLOW.md` → Diagrams). Never hand-author Excalidraw scene JSON.
9. Write to `vault/<Section>/<Natural Title>.md` — or the matching subfolder where one exists (`vault/Shelf/Books/…`, `vault/Shelf/Movies|Shows|Videos/…`), its cover in that folder's `covers/`; loose media goes in the section's `attachments/`. Then report path, future URL, links added, images fetched + sources, and anything you fixed or assumed.

## Common tasks

- **New page style** (e.g. projects grid): see `docs/ADDING-PAGE-TYPES.md`. Component in `components/lists/`, register in `lib/section-types.tsx`, set `type:` in the section's `main.md`.
- **Any UI work**: wrap the route's content in `<Page>` (never re-type a container), reach for the tokens rather than literals, give clickable things `press` (`press press-soft` for cards), and don't add `transition-colors` beside `.press` — it declares its own. Then check the result in **both languages, light and dark**.
- **Editing `globals.css`**: it has no `@layer`, so position is the tie-breaker — an override belongs BELOW what it overrides. This has caused four separate bugs (`docs/DECISIONS.md` #51, #52, #55, #81), the subtlest being a `transition:` shorthand hundreds of lines above silently resetting a later `transform`. **A bare class selector here also beats a Tailwind utility of the same specificity**, so never set `position`, `display` or `width` on a class whose element carries a utility for it — `.chrome-bar { position: relative }` overrode `fixed` and dropped the floating breadcrumb into the page flow at full width (#81).
- **Refreshing IMDb ratings**: `node scripts/imdb-ratings.mjs` rewrites `imdb:` on every shelf note that carries an `imdb_id:`; `--check` reports drift and changes nothing. Source is IMDb's own daily dataset (datasets.imdbws.com, keyless, personal/non-commercial use). **`imdb_id:` is never guessed** — add it by hand from the title's Wikidata item (property P345), because `Seven`, `Dark` and `Prisoners` each name several films and a wrong id prints a confident wrong number. `docs/DECISIONS.md` #114.
- **New video on the shelf**: videos arrive from a public YouTube playlist, not from watch history (which Google closed in 2016). `scripts/youtube-shelf.mjs pending` lists playlist videos with no note; the agent writes the note. Full workflow: `docs/YOUTUBE-SHELF.md`, reasoning in `docs/DECISIONS.md` #109.
- **Verify changes**: `npm run build` must pass — it statically generates every page and will surface broken content/code. `npm test` runs Node's own runner (no framework) over `lib/*.test.ts` **and `scripts/*.test.mjs`**; it is wired through `--import ./scripts/test-hooks.mjs`, which registers `scripts/test-resolve.mjs` on the loader thread to teach it the `@/` alias and extensionless imports. `npm run validate:image-notes` gates both `predev` and `prebuild`, so a broken image note fails `dev` and `build` before Next.js starts.
- **Verifying a Tailwind class actually shipped**: grep the built CSS for the ESCAPED form (`.w-\[calc\(…\)\]`), or read the element's computed style. A plain grep finds nothing whether or not the rule exists, and "nothing" looks exactly like "never emitted" — that misreading is written up in `docs/DECISIONS.md` #54.

## Features to know about

The current entry model exposes `description_uk` as `Entry.descriptionUk`.
Movie/show Top lists also accept the optional `top_order:` frontmatter key;
localhost drag editing writes consecutive positions and takes precedence over
the derived rating/IMDb/date fallback. See DECISIONS #119.

- **Sidebar, two ways in** (`components/Chrome.tsx`, `docs/DECISIONS.md` #74): the panel icon opens the drawer by click, and putting the pointer on the left edge of the window (`.edge-zone`, a 16px strip, `(hover: hover) and (pointer: fine)` only — on touch it would swallow the back-swipe) opens it too. `openBy` (`"modal" | "peek" | null`) records WHICH KIND, because they mean different things: a deliberate open — the icon, or the `m` key — is modal (backdrop, focus trapped, stays until dismissed), the edge is a peek (no backdrop, not `aria-modal`, focus untouched, closes ~180ms after the pointer leaves the panel — delayed so clipping the corner doesn't slam it shut, and it stays open if the keyboard is inside). Clicking the icon (or pressing `m`) while peeking PROMOTES it to modal rather than closing.
- **First-visit intro** (`components/Intro.tsx` + a gate script in `app/layout.tsx`, maths in `lib/intro.ts`, `docs/DECISIONS.md` #79): a reader's FIRST EVER visit to home opens on an empty page with the greeting typing itself; the photo fades in the moment the first name lands, and a beat after the full stop the rest of the page sweeps in line by line and the chrome fades up. Once per browser (`INTRO_KEY = "intro-seen"` in localStorage — clear it to see the intro again). The REAL `<h1>` is what types: it's split into `.tw-c` per-character spans in place and reassembled as a plain text node at the end, so the sentence is never duplicated in a component where it would drift from `vault/Home/main.md`. Untyped characters keep `visibility: hidden`, so the line never rewraps mid-type. The photo is cued by `photoCue()` finding the first name in the sentence, NOT by a character count — it survives rewording and works in Ukrainian, and returns Infinity (photo arrives with the body) if the greeting doesn't say the name. Everything is hidden by CSS keyed to `data-intro` on `<html>` and nothing is hidden in the HTML, so no-JS, crawlers and Reader mode get the whole page; `prefers-reduced-motion` never arms it. Three independent ends: any click/key/scroll/touch, the driver's own completion, and an 8s failsafe plus early pointer/key listeners in the gate script — a hidden page must always come back, including before hydration exists. The gate lives in the layout because only an inline `<head>` script runs before the first paint (hence its `pathname === '/'` check) and it writes `INTRO_KEY` itself so "armed" and "seen" are one decision; the client half covers soft navigations, which the gate never sees. `npm test` asserts the sequence stays inside the failsafe. **Three things here are load-bearing and were each a visible flash before review:** the heading is hidden outright until the driver adds `.tw` (otherwise the server's finished sentence paints, then vanishes when hydration runs); the chrome is hidden/revealed by NAME (`.skip-link`, `.chrome-bar`, `.edge-zone`) and never as `body > *:not(main)`, which also caught the drawer's `bg-black/25` backdrop and the closed dialogs and faded a dark sheet over the page on the way out — anything that manages its own visibility must be left to; and the character spans are NEVER reassembled, because one inline box per character breaks kerning across the boundaries and restoring the text node would make the title settle a pixel or two. Skipping fades over 160ms with the stagger dropped (`[data-intro-fast]`) rather than cutting.
- **Note constellation** (`components/Constellation.tsx` server → `components/ConstellationStrip.tsx` client, maths in `lib/constellation.ts`, `docs/DECISIONS.md` #80): the drawer's footer shows six months of writing as ONE BAR PER WEEK, height = that week's note count against the busiest week. Built at build time from every dated entry, so it never needs maintaining. It was a GitHub-style DAY grid first and that was thrown away after looking at the real vault through it — 25 notes on 5 days, 14 of them in one sitting, which reads as abandoned; the day a shelf note is typed isn't the day the book was read, and weekly buckets absorb that. `WEEKS = 25`, bars 6px + 1px gap = 174px, which is what fits the `w-56` drawer's 176px of inner width: **the bar width, the gap and `WEEKS` are one decision written in two files** and both say so. Height carries the count so tone doesn't (every bar the same weight — no ramp, monochrome, #64). The "6 months · N notes" line (range first — the strip is a picture of a span of time) is HIDDEN until `:hover`/`:focus-within`, goes quiet again while a week is open (`data-open` on the section, rule placed after the hover ones so it wins by position), and a bar's own summary appears UNDER THAT BAR on hover as "16.07 · 14n", hanging into the section's bottom margin so the strip stays at the foot of the drawer (`sr-only` keeps the full sentence for screen readers). Its column position is `--x = index × 7px` — arithmetic off the 6px bar + 1px gap, not a measurement — and labels in the last few columns flip to right-aligned so they can't run off the drawer; the component decides which, since only the index knows the room left. `shortDate` lives in **`lib/dates.ts`**, not `lib/vault.ts` — `PostRows` needs it and is rendered by `PostListClient`, so it reaches the browser and can't import anything that touches `fs`. Clicking a bar opens THAT WEEK'S NOTES directly above the strip, IN FLOW and styled as the sidebar's own nav rows (`-0.75rem` pulls them out of the footer's `px-6` into the nav's `px-3` column; one size down because a note title is a sentence, not a word). It was a bordered/blurred popover first and that read as a separate app parked over the drawer. One list refilled per week, so no titles are in the page HTML until something is clicked; `inert` when closed, Escape or the same bar closes it. Outside clicks close it through a `pointerdown` LISTENER, never a backdrop element — a fixed overlay would eat the first click on every nav link above it. The drawer closing collapses the week as well, watched with an `IntersectionObserver` on the strip rather than by subscribing to Chrome's state (the strip is handed to Chrome as an opaque element, and the observer holds however the panel goes away). **The section list outranks the week list**: in flow the week's height comes out of the scrolling `nav`, so it's capped at `min(28vh, 10rem)` — about five rows, shorter than the section list — and a busier week scrolls inside it. That cap and the overflow sit on the `<ul>`, not the block around it, so the week's date stays put while the notes move under it. **Under `max-height: 700px` (or the 639px phone width) it becomes a floating card instead**, because on a short window taking room from the scrolling nav would squeeze the sidebar's actual job to nothing; the strip's height is shared as `--strip-h` so the card can't drift onto the bars. Bars are buttons, not links: that gives up the no-JS version deliberately, since a popover of choices has no honest static form in a 176px column. Rendered by `app/layout.tsx` and passed to `Chrome` as an ELEMENT — `Chrome` is a client component and importing it would pull `lib/vault.ts`'s `fs` into the browser bundle. `today` is a prop, never a clock read, so the strip is testable.
- **New since your last visit** (`lib/new-notes.ts` + `components/NewBadge.tsx`, `docs/DECISIONS.md` #84): a note that arrived after your last visit is marked in every section list except `now` (and on home's recent-posts list). THREE SHAPES, one component: `chip` (default) follows a title in a row of text — posts, projects, music, home — as a monochrome outline; `cover` is for shelf and people cards, where it becomes a pill ON the artwork in the same dark-scrim material as the shelf's `Reading` badge, in the OPPOSITE corner (`.shelf-status` left, `.cover-new` right, one shared rule block) so a card can carry both; `dot` is for a book spine, which is 44px wide — a 5px mark at the head of the spine in the spine's OWN ink, with the word kept as `sr-only` text. `now` is excluded on purpose: it is about the present, so everything on it is current and a New mark says nothing. `ShelfItem` and `PersonRow` had to start carrying `date` for this. The chip is `.new-chip` in `globals.css` and shares ONE geometry rule with `.draft-chip`, NOT a string of utilities. **The placing is `vertical-align: 0.11em` and that is the load-bearing part** (#116): small text sharing a big text's baseline sits OPTICALLY low — the chip's caps are 8px against a 16px title's 10.7, so their midlines are 1.34px apart even with the baselines in perfect agreement. The lift closes that to 0.02px. Two earlier passes tried to fix it by moving the BOX instead (asymmetric padding, then `line-height: 1` to cut the box from 22px to 19px and its overhang below the baseline from 6px to 4px); both are still there and both help, but neither was the answer, and this file previously said `vertical-align` was the wrong tool — it was the right one. The padding is symmetric now because the lift does the placing. Draft carries a TRANSPARENT border so its filled box matches New's outlined one to the pixel. Two exceptions: the music list strips the chip back to plain text via `.music-meta > span` (structural, outranks `.new-chip`), and `.draft-chip-title` beside a note's 46px `<h1>` keeps `vertical-align: middle` and a 3px lift, since any baseline rule puts a 19px chip at the foot of a 30px cap. One localStorage key (`notes-seen`) holds `{prev, last}`; the marker advances once per SESSION (a gap over `SESSION_GAP_MS` = 30min starts a new visit) rather than once per page load — stamping it on arrival would clear every badge with the first page you opened — and the answer is memoized for the life of the page so a soft navigation doesn't clear the row you're looking at. A note dated D is read as arriving at the END of day D and compared against the previous visit's TIMESTAMP (`prevAt`) — NOT as two `YYYY-MM-DD` strings, which was the first version and meant a note published on a day you had already visited could never badge for you at all, so it never fired for the readers who come most often. The bounded cost: a note dated on your previous visit's day stays badged one visit longer. `parse()` still migrates the day-string shape that briefly shipped. Nothing older than `MAX_AGE_MS` (30 days) is badged and a FIRST-EVER visit badges nothing. Client-only and starts hidden, like the series read counts — and it's a component rather than a hook because `PostRows` also renders on the server as `PostListClient`'s Suspense fallback. Monochrome on purpose: Draft's amber is a dev-only warning, the published page has no accent colour (#64).
- **Local authoring dock** (`components/DevTools.tsx`, `components/DevRatingEditor.tsx`, `components/DevTopReorder.tsx`, `scripts/dev.mjs`, `scripts/dev-editor*.mjs`, DECISIONS #118–119): `npm run dev` starts Next and a separate writer bound to `127.0.0.1`; a development-only rewrite gives the exact `localhost` page same-origin access. The collapsed preview shows only a bottom-right pencil and leaves public chrome unchanged. Expanded, it opens the same route on `siteUrl`, opens the active EN/UK source through an absolute `obsidian://open?path=…` URI, switches language, edits `title`, `title_uk`, `description`, and `description_uk`, and turns movie/show Top-list stars into a pointer/keyboard rating slider. Top-list rows can also be dragged into a manual order; the sidecar writes sequential `top_order:` values to the participating notes, and that order takes precedence over rating/IMDb/date. Undo/Redo/Cancel are browser drafts; Save uses an exact-byte revision and atomic replacement, and conflicts keep the draft. Source paths come from the dock-only `data-dev-vault-source` marker and are realpath-checked beneath `vault/`; Top-list sources are exposed only to the development editor. Never derive a write path from the URL. Body editing and attachments remain Obsidian work until their source-map and asset-transaction contracts exist. The UI requires both a development build and `window.location.hostname === "localhost"`; the sidecar independently checks the exact origin and session token. Use `npm run dev`, not bare `next dev`.
- **The sidebar's last line, and the fifteen days it changes** (`components/ResistanceDay.tsx`, dates + kinds in `lib/observances.ts`, words in `observanceName` in `lib/ui-strings.ts`, both treatments at the foot of `globals.css`, `docs/DECISIONS.md` #104): normally "Day N of Ukraine's resistance" (`lib/resistance.ts`, counting from 20 Feb 2014), a quiet monobank donation link styled as nothing at all (#37). On Ukrainian national days it names the day instead, and **`kind` on the row is the only thing that picks the treatment** — adding a day is one line in `DAYS` plus one string pair, and nothing else learns a new name. Eight `celebration`s (Unity, Vyshyvanka, Constitution, Flag, Independence, Defenders, Dignity and Freedom, Armed Forces) take the flag, blue over yellow; seven `remembrance` days (Heavenly Hundred — 20 Feb, also day 1 of the count — the full-scale invasion 24 Feb, Chornobyl, Remembrance and Victory over Nazism, Day of Mourning, fallen defenders 29 Aug, Holodomor) **never** do. Mourning is not celebrated in the national colours; `.observance-quiet` drops the gradient for `--text-secondary`, which is the site's own register for grave emphasis (#64) — and it must sit BELOW the `@supports` block, not merely below `.observance`, or the transparent `-webkit-text-fill-color` survives and every remembrance day renders as a blank line (that exact bug happened). The flag colours are `--ua-blue`/`--ua-yellow`, and they are NOT the flag's own hex values — `#FFD700` on white is invisible at 11px and `#0057B7` on a near-black page is a hole, so light mode takes a deeper gold and dark mode the true yellow with a lifted blue; what carries is the RELATIONSHIP, blue over yellow, legible in both. **They are not an accent token and must not become one** (#64 stands), and the celebration line is held at `opacity: 0.7` so it greys back to roughly the weight of the `--text-tertiary` counter it replaces — at full strength it out-pulled everything else in the sidebar. Opacity rather than duller tokens, so one number mutes both themes; 0.55 is too far, the gold half vanishes on white. The split is one hard-edged two-stop gradient clipped to the text — a fade would read as a rendering effect, not a flag — and `line-height: 1` on the inline-block is load-bearing: the gradient measures against the element's box, so at the paragraph's 1.5 the seam falls below the letters and the line paints entirely blue. **62% is measured**, not chosen: tight to the text the box is one font-size tall, and Source Serif's metrics put the middle of a lowercase letter there. Both languages must fit the sidebar's 176px on ONE line at 11px — **every string was measured in the browser**, which is what rules out the fuller official titles (`День пам'яті жертв Голодоморів` is 174.5px, 1.5px of margin, so it was shortened). Vyshyvanka Day (third Thursday of May) and Holodomor Remembrance Day (fourth Saturday of November) MOVE and are placed by `nthWeekday()`; November is where that has to be right, since Holodomor falls 22–28 and Dignity and Freedom Day is the 21st. Day and observance are both passed from the layout as build-time props AND re-read from `new Date()` in one effect, because the site is static and a deploy from the 23rd would otherwise still say Flag Day on the 24th. - **Cmd+K runs actions too**: switch language, copy page as Markdown (clicks the existing `button.copy-md`), copy link, open this note on GitHub (`repoUrl`/`repoBranch` in `lib/site-config.ts`; path read from `data-vault-source` on the entry page — **this one needs the repo to stay public**, or every reader who isn't Kyrylo gets a 404 and nothing here can tell; take the repo private and clear `repoUrl` in the same change, `docs/DECISIONS.md` #39), random note. Pages always sort above actions. A leading `>` scopes the search to the current page and its headings; `>` alone prints the note's outline.
- **Reading position** (`components/ReadingPosition.tsx`): remembers how far into a note you got and *offers* to return — never scrolls on its own. One localStorage key, map of path → position, pruned to 20 notes / 30 days, written on a debounce rather than per scroll frame. The offer withdraws on reader-generated scrolling (`wheel`/`touchmove`/scroll keys), NOT on a scroll threshold (#47), and is only made when you land more than half a screen from the saved mark — landing ON it means the browser already did the job (#49). Add `?rp=debug` to any note's URL to print why the offer was or wasn't made (#48).
- **Image dimensions**: `sync-assets.mjs` writes `.image-manifest.json` (blur placeholder + `w`/`h` per raster); `rehypeImageSize` in `lib/markdown.ts` stamps `width`/`height` on content images so nothing shifts as they load. Explicitly sized embeds (`![[me.jpeg|93]]`) keep their size.
- **Responsive images**: `sync-assets.mjs` also writes 256/672/1344px WebP copies beside each raster (never touching the originals) and a ready-made `srcset` into the manifest. `rehypeImageSize` stamps it on content images with a `sizes` matching the prose column (or the embed's own width); shelf and people covers carry it via `coverSrcSet`. `srcSetFor()` in `lib/blur.ts`.
- **Motion that answers** (#66): an arrow leads on hover and is thrown in its direction on press and STAYS thrown — `components/ArrowThrow.tsx` adds `.is-thrown` at the click, because `:active` ends before the next page paints and the arrow used to race back (`Shortcuts` adds the same class for `[`/`]`). `.sibling-arrow` in the entry footer, `.arrow-glyph` on standalone action links (`.action-link`: "Continue reading", "All posts", "← Back home" — `.is-back` leads and throws the other way); arrows live in spans, never inside a translated string; the lightbox arrows throw shorter and don't fade, since you stay in the gallery. Checkmarks DRAW (`stroke-dasharray`, paths written short-arm-first so the stroke runs the right way) — an animation on the copy button, which goes from `display:none`, a transition on the always-mounted series checkbox. Prose links (`p`/`li`/`blockquote`/`td` only) sweep their underline from the left using two background gradients — `text-decoration` can't grow from one end, and the trade-off is losing `skip-ink`, so the rule sits below the descenders and everything else keeps the plain decoration. The Cmd+K selected row is one `.palette-marker` that slides, measured from the live DOM like the ToC marker.
- **Motion** (`docs/DECISIONS.md` #38, #44, #45): `.stagger` on a list container makes its children arrive one at a time (nth-child delays, capped at 12; `animation: none` under reduced motion and print, since a shortened duration still honours the delay). Navigations fade via `.page-in` — they briefly ran through the View Transitions API and it was reverted for feeling laggy (#45); the API survives only in the lightbox, which opens as a zoom out of the figure you clicked (`lib/view-transition.ts`). Shelf rows are drag-to-scroll, no edge fade and no arrows (`components/lists/ShelfRow.tsx`). A fixed `feTurbulence` tile on `body::after` grains the background. The ToC rail highlight is one sliding `.toc-marker` positioned from the live DOM. Dialogs (palette, shortcut sheet, ToC sheet) stay mounted and toggle `data-open` so they animate shut, with `inert` when closed and contents gated behind first open to keep them out of every page's HTML. **Pressed state** (#55): `.press` dips a control to 97% while held (`.press-soft` → 99% for cards, via `--press-scale`) — opt-in, because a scaled inline prose link reads as a rendering fault; the named components join in by selector at the very END of `globals.css`, since their own `transition:` shorthands sit hundreds of lines above and would otherwise reset transform away. `.lightbox-arrow`/`.selection-pill` compose the press with the transform they're positioned by.
- **Series** (`lib/series.ts` + `components/Series.tsx`): `series: Road to Security+` in an entry's frontmatter joins it to a multi-part arc — a "Part 2 of 5" badge beside the date which opens a popover listing every part (built like the mobile ToC sheet: always mounted, `data-open`, `inert` when closed, contents gated behind first open; anchored under the badge at every width, nudged left by a measurement when it would overflow the window). Matching is by name (case/space-insensitive) and **vault-wide**, so a series can run across sections; no route or URL changes. Order is oldest-first, overridable per note with `part: 2` (for same-day or backdated parts). `series_uk:` is written on any ONE part and used for all. A series with a single published part renders nothing. See `docs/DECISIONS.md` #42.
- **Link hover previews**: internal links in `.prose` show a preview card on hover — title, excerpt, date, cover — from `getLinkPreviews()` in `lib/previews.ts`. Mounted per page (home, section, entry) with `previewsInHtml()`, which scans that page's rendered HTML and passes only the previews it can actually use — the layout used to hand every page all of them. Pointer devices only; the card is non-interactive. The cover **floats** and the excerpt wraps under it, sized from the image's own `coverAr` (intrinsic w/h, via `dimsFor()`) inside an 80 × 84 box — every cover keeps its true shape, from a 0.60 paperback to the square People portrait to a 5:1 logo banner, and a cover that can't fit shrinks rather than being cropped. **Nothing inside the card may take `overflow` or `display: -webkit-box`**: either makes its own formatting context, which sits beside the float instead of flowing round it, so the title/excerpt line clamps are gone and `EXCERPT_CHARS` (140) is what bounds the card's height. A card with NO cover shrinks to its text (`fit-content`, 13rem floor, 20rem ceiling) so a one-line section description isn't a 320px slab; one WITH a cover takes the ceiling via `data-cover` on the card, because a floated cover is out of flow and contributes nothing to `fit-content` — measure the text alone and the artwork gets squeezed into the remainder. `docs/DECISIONS.md` #85.
