# CLAUDE.md — AI assistant context

Context file for AI models working on this repo. Read this first, then `docs/ARCHITECTURE.md`.

## What this is

Kyrylo's portfolio site, published from an Obsidian vault. The `vault/` folder IS the CMS: TOP-LEVEL folders → section pages, `.md` files inside them → entries with their own URLs. Pipeline: Obsidian Git → GitHub → Vercel auto-deploy. Fully static (SSG), no database, no runtime fs access.

Sections may hold subfolders (`vault/Shelf/Books/`, `vault/Shelf/Books/covers/`, `vault/Posts/attachments/`) — they're filing, for the owner's benefit in Obsidian. A subfolder never becomes a page and never appears in a URL: an entry's slug comes from its file name, so a note can move between folders without breaking its address.

## Owner context

- Kyrylo, high-school student in Ontario, heading into cybersecurity (Security+, then Cyber Science at TMU). Not a professional developer — keep changes simple, documented, and low-maintenance.
- Design reference: brianlovin.com (sidebar rail, list-detail, near-black dark mode). Original implementation, inspired only.

## Hard rules

1. **Never make content edits outside `vault/`** unless asked — content belongs to the owner via Obsidian.
2. **Keep the site fully static.** No runtime fs reads, no server actions for content. Everything resolves at build time via `generateStaticParams`.
3. **Keep `vault/` conventions stable** (top-level folder + `main.md` = section; other `.md` = entries, at any depth inside it). Breaking these breaks the owner's Obsidian workflow.
4. **Update `docs/DECISIONS.md`** when you make a non-obvious architectural choice.
5. Assets: never reference vault files directly from components — they're mirrored to `public/vault-assets/` by `scripts/sync-assets.mjs` (runs via predev/prebuild).
6. **Two agents work here.** Keep `CLAUDE.md` and `AGENTS.md` in step, and never leave the tree half-edited — see below.

## Two agents work on this repo

Claude Code and Codex are both used here, on the same checkout. Each auto-loads its own file:

|---|---|---|

- **Code and `docs/DECISIONS.md` are the source of truth.** Where prose disagrees with the code, the code wins — say so rather than "fixing" the code to match a stale sentence.
- **Change a convention, command, or invariant → update BOTH agent files in the same change**, plus `docs/DECISIONS.md` if the choice is non-obvious. These two files have already drifted apart once (each described a different `npm test` wiring), which is exactly the failure this rule prevents.
- **`AGENTS.md` must not restate feature detail** that this file owns — it should point here instead. Duplicated prose is what drifts.
- **One agent at a time in this working tree.** Obsidian Git auto-commits *everything* (`autoCommitOnlyStaged: false`) every 10 minutes and pushes, and Vercel deploys the result — so a half-finished edit publishes itself on a timer. Finish and verify a change, or work in a separate `git worktree`. Don't run Claude and Codex against this checkout simultaneously.
- **Check `git status --short` before editing.** Uncommitted changes you don't recognise may be the other agent's or the owner's in-flight work: leave them alone and ask. Never `git restore`, `git checkout --`, or `git stash` a file you didn't change yourself.

## Conventions

- Home is the section whose slug is `home` (`app/page.tsx`); `lib/section-types.tsx` is the registry mapping a section `type` to its list component.
- Icons (`components/icons.tsx`) are **rendered in the sidebar only** — no icons on page content (#64). `resolveIcon()` maps vault frontmatter emoji/names → SVGs; unknown emoji render as text.
- Frontmatter (section `main.md`): `title`, `icon`, `order`, `description`, `type`, `slug` (override), `draft`. Full frontmatter is exposed as `section.meta` so section types can define their own keys (e.g. `music` reads `playlists:`).
- Section types: `posts` (default; category filter chips from entry `category:` frontmatter — chips are links to `/posts?category=X`, read by `useSearchParams()` in `PostListClient`, so a post's own category chip lands here pre-filtered. Unlike the shelf these are NOT separate pages: no per-category title/OG/sitemap entry, and filtering needs JS), `music` (Apple Music iframe embeds — `lib/apple-music.ts`, no API key — plus an Apple-Music-style TRACK LIST for the notes: entry `cover:` (an album cover, resolved by `resolveCoverUrl()` exactly as the shelf and people lists resolve theirs) renders as 44px square art, and the row is placed by grid AREA — `"art title date" / "art desc desc"` — so the description gets the date's width back instead of being truncated to nothing on a phone. Its divider starts at the TEXT column, not the row's edge, which is the most recognisable thing about an Apple list and does more work than any typeface would. Dates stay FULL (DD.MM is posts-only). **No play triangle on hover** — the row opens a note and nothing plays. The list sits in a CARD (`.music-card`, `--surface` + `--border` + `--r-xl`, matching the embed above it) whose colour is the NEWEST note's cover, blurred past recognition and clipped to it (`.music-wash`) — the mask stops at 35% rather than transparent, or the card reads as a coloured band with a plain list under it. It was full-bleed behind the page header first; contained, the artwork is inside a frame like every other picture here and #64 stands as written. The wash is an earlier SIBLING of the list, so ordering is `position: relative` on `.music-tracks` alone — no `z-index`, and never `isolation` (#81). Row hover is `color-mix(in srgb, var(--text) 7%, transparent)`, NOT `--bg-hover`, which is opaque and blanked the tint for the length of the hovered row. Entry descriptions are translated by reading `description_uk` out of `entry.meta`, since `Entry` models no `descriptionUk` — move it onto `Entry` when a second list wants it. Covers come from the keyless iTunes Search API (`artworkUrl100` → `600x600bb`) into `vault/Music/covers/`. The 1:1 album ROW is specified and deliberately unbuilt — it's `ShelfRow` with the aspect changed, waiting on there being four or five notes. A music NOTE opens like a shelf note (`docs/DECISIONS.md` #91): an artist block above the body from `artist:` (+ `artist_uk:`, `artist_photo:`, `artist_bio:`/`artist_bio_uk:`) whose role reads **Artist** — `entryCreator()` picks the role from WHICH KEY the note used, `artist:` or `author:`, so it needs no knowledge of the section — then a plain fact list, with `rating:` appended as its last row exactly as on the shelf. The note also tints its own opening with its own cover (`.note-wash`) — a WASH, dissolving on every side, never a card, because `.creator` is deliberately unframed (#86). It is anchored to `main` via `:has()`, not to `.page`, so it spans the WINDOW rather than the 39rem column (#92): `main` is already full width, so `left/right: 0` needs no `100vw` and cannot make a horizontal scrollbar. Note the section card and the note wash pull opposite ways on purpose — the list is an object you look at, so it is framed; the note's colour is the room it sits in, so it dissolves. Music notes get a SQUARE OG card (`coverShape: "square"` in `lib/og.tsx`, which replaced the old `wide?: boolean`) and `MusicAlbum` JSON-LD with `byArtist`, wrapped in a `Review` when rated. `docs/DECISIONS.md` #90, #91), `people` (cover-image grid; entry `cover:` frontmatter, initials fallback), `shelf` (Netflix-style: one horizontally-scrolling row per medium, each linking to `/<section>/type/<medium>`; entry `cover:` + `author:` + `medium: book|movie|show|video` (omit it and the subfolder decides — a note in `Shelf/Movies/` is a movie; `entryMedium()` in `lib/shelf.ts`) + optional `rating: 0–5` halves allowed + optional `coverFit: contain` (letterboxes wide art instead of cropping — a LAST RESORT, and unused in the vault today: Mr. Robot's title-logo cover was replaced by a real poster) + optional `status: reading` (also `watching`/`current`/`in-progress`) which badges the cover "Reading" or "Watching" depending on the medium — anything else, or no key at all, reads as finished and stays unlabelled; alias `books`. `medium: video` + `video: <youtube url>` renders a 16:9 card with a play badge and derives the thumbnail from the video ID — no `cover:` needed; optional `uploaded: YYYY-MM-DD` (the VIDEO's publish date, not the day it was shelved) is what upgrades the page's JSON-LD from `CreativeWork` to a full `VideoObject` — the site can't derive it, so without it the video markup is deliberately not emitted (`docs/DECISIONS.md` #41). Every shelf ENTRY PAGE opens with a creator block above the note's own body — round portrait, role, name, short bio (`components/Creator.tsx`, data from `entryCreator()` in `lib/shelf.ts`, `docs/DECISIONS.md` #86). The ROLE is derived from `medium:` (book → Author, movie → Director, show → Creator, video → Channel, bilingual via `lib/ui-strings.ts`) and is never written in the note. Frontmatter: `author:` (the only required key — nothing else has to be there; a MUSIC note writes `artist:` instead, same shape, and that key is what selects the Artist role) + optional `author_uk:`, `author_photo:` (resolved like `cover:`; portraits live in the shared `vault/Shelf/creators/`, square-cropped to 320px BEFORE entering the vault, since centring `object-fit` on a stage photo misses the face), `author_bio:`/`author_bio_uk:`. Each field degrades on its own: no photo falls back to initials (first + LAST word, `|` and anything after it dropped, so a channel written `Nate Herk | AI Automation` is `NH`), no bio leaves role and name standing. Every current note HAS a portrait, so the initials path is exercised by `npm test` rather than by the vault — don't assume it's dead code. Sourcing them is a cascade, not one lookup (`docs/CONTENT-WORKFLOW.md` → Images & media sourcing): en-Wikipedia's `pageimages` is only the first guess (it returned Richard Bach's SIGNATURE), other languages and a direct Commons search come next, `prop=globalusage` confirms a file that might be someone else, then the creator's own site — and **for a video, the channel's own YouTube avatar**, which is `oembed → author_url → that page's og:image`, keyless and already square. A channel's avatar is right where a photo of its host would be wrong: `author:` names the channel. The portrait keeps its COLOUR and must not borrow `.person-photo`, whose greyscale is a hover-only exception (#56) and would be permanent here; full-colour artwork already sits at rest on every shelf page. **The fact table must not also carry an Author/Channel row** — it was deleted from every note and its `.uk.md` sibling when the block shipped, and re-adding it prints the same fact twice. Row order and grouping live in `lib/shelf.ts`. Videos keep their native **16:9**, uncropped, and are made smaller instead: `--shelf-video-h` is two thirds of `--shelf-card-h` (~226 × 127 vs ~127 × 190 for a cover), so the video row is shorter than the cover rows by a fixed ratio rather than by accident (`docs/DECISIONS.md` #54). Grid pages are unaffected; there the column width leads. `categories: [Tech, Education]` (multi-valued) drives filter chips on the medium page and renders as `#tags` at the END of the entry's metadata line, not on a row of their own — the section page shows neither), `projects` (TIL-style inline feed; async list component), `now` (nownownow-style page: a “Short-term goals” checklist plus an optional résumé, both written as MARKDOWN IN THE BODY and parsed by `lib/now-content.ts` into the `goals`/`resume` shapes the components read — `## Goals` is a task list (`[x]` = done, indented bullet = sub-label, trailing `→ [[Note]]` = link), `## Résumé` is a summary paragraph + one `###` per block + one `#### Role · Org` per timeline row with `*period* · sub-label #current` on that same line. Frontmatter keeps flat keys only: `updated:`/`updated_uk:`, `resume_file:`. Ukrainian goes in a sibling `main.uk.md` with the same structure, merged by position; flags and links are read from `main.md`. Anything above the first heading renders as intro prose. See Features + `docs/DECISIONS.md` #26). Markdown pipeline also auto-embeds standalone Apple Music and YouTube links (`lib/youtube.ts`, served from youtube-nocookie.com; handles watch/youtu.be/shorts/live URLs). **The Apple Music embeds have NO footer link** — an "Open in Apple Music" one existed so a stalled gray-skeleton embed was never a dead end (#10) and was removed (#92), because a loaded player already carries Apple's own links to the same place directly above it. `ui.openInAppleMusic` is parked, translated, for whenever the stalled case argues itself back. An embedded player is also the answer to "can people listen without leaving the page" — they already can: previews for everyone, full tracks for a signed-in subscriber, no key and no JS of ours. A SONG link (`?i=…`) gets the compact 175px player, an album the 450px one. Both washes fade in via `@keyframes wash-in`, which names only `from { opacity: 0 }` — with `both`, the end state is each element's OWN opacity, so light (0.30) and dark (0.36) are both honoured; **never add a `to:` there**, it would flatten dark mode to the light value (#92).
- Filterable lists are split server/client: `PostList`→`PostListClient` (server slims entries to serializable rows). The shelf is fully server-rendered — medium rows replaced its filter chips, so it needs no client state.

Callouts keep their four hues (there colour carries meaning), and the hover-only exceptions stay. Active chips/nav use text-on-bg inversion. Two sanctioned exceptions, both hover-only so the page at rest is unchanged (`docs/DECISIONS.md` #56): people photos sit at `grayscale(0.3)` (`.person-photo`) and return to full colour, and the four platform icons take their brand colour (`.social-link[data-social]`, `--brand`, with near-white stand-ins for GitHub/X in dark mode; mail has no platform, so it keeps `var(--text)`). `@media (hover: none)` drops the photo filter — on touch there'd be no way back.

On home, and on a section's own page, only the site name remains. ## Design system

Full reference: `docs/ARCHITECTURE.md` → Design system. The short version:

- **Never re-type a page container.** `components/Page.tsx` owns measure, gutters and rhythm (`--measure`, `--gutter`, `--page-y`). It used to be `max-w-2xl px-6 py-14 lg:py-24` copy-pasted into seven route files, two of which had already drifted (`docs/DECISIONS.md` #58).
- **Use the tokens, don't type literals** (#58). Radius `--r-xs|sm|md|lg|xl|full` (4/6/8/12/16px + pill, equal to Tailwind's scale so the two can't drift). Motion `--ease` + `--dur-fast|--dur|--dur-slow` (120/200/320ms; Tailwind's `--default-transition-*` point at them, so utility classes move the same way). Surfaces: `--surface` is a card/cover/badge FILL, `--bg-hover` is the pointer response, `--chrome-bg`/`--chrome-ring` are the floating bars and pills (built from `--surface` in dark mode — a pill made of `--bg` is invisible on a dark page, `docs/DECISIONS.md` #60). `.chrome-bar` and `.toc-bar` share a LAYERED blur — two masked pseudo-elements instead of a `backdrop-blur-*` utility — so their edges dissolve rather than ending at a hard rim. Their `z-index: -1` layers rely on each pill's own `z-index` for its stacking context — **never add `isolation: isolate`**, which forms a backdrop root and stops `backdrop-filter` sampling anything behind the element (#81). `.sidebar-panel` deliberately takes ONE even blur on the element itself: graduating it across 224px is wide enough to see as a seam down the middle, so the panel reads as two panels side by side rather than one dissolving edge — graduation is for surfaces small enough that their edges are most of them. The drawer's hairline must stay an INSET `box-shadow`: an outset one leaves a 1px line down the left of the window whenever the panel is parked off-screen, and a shadow rather than a border costs no layout — the constellation's strip is measured against the full `w-56`. The modal backdrop covers the WHOLE viewport, panel included — two attempts to stop it at the panel's edge (a static `left-56`, then a transform tracking the slide) both produced a doubled edge: the page reads bright through the translucent panel and dark beside it, so the sidebar looks like a window cut out of the page. A translucent panel over a dimmed page is meant to be darker. The tell was that it only showed when opening by the icon, never by the edge peek — which has no backdrop (#74, #80).
- **`.press`** (#55) dips a control to 97% while held; `.press-soft` (99%) for cards. Opt-in — a scaled inline prose link reads as a rendering fault. Named components join by selector at the very END of `globals.css`; don't move that block up.
- **The design itself** lives in one block at the FOOT of `globals.css` (`docs/DECISIONS.md` #59): Source Serif 4 for everything except code (sidebar and `svg.diagram text` included), big fluid `.page-title`, wide tonal range, dark mode with real elevation (`--surface` above `--bg`), demoted `.entry-meta`/`.entry-tags`, generous space above `h2`. It shipped as one of two switchable themes while the choice was being made; the switch and the losing design are deleted.
- **Any new UI must work in both languages, light and dark, and under `prefers-reduced-motion`.** Using the tokens is what makes that nearly free.
- **One typeface — Source Serif 4, everything except code**, self-hosted via `next/font` with the `cyrillic` subset AND `axes: ["opsz"]` (#61). Script coverage is a hard filter applied before a typeface is judged on looks: every note has a Ukrainian translation, and Newsreader was chosen and dropped for exactly this (#59). Quotes are the same family in italic — don't reach for a second family, that's what Lora was and it had to go.

## Content intake (most common task)

When Kyrylo hands you raw content (a post, book/movie thoughts, a project
update), follow **`docs/CONTENT-WORKFLOW.md`** — the full playbook. Core rules:

1. Light-touch editing only — fix typos/grammar/structure, never his voice or opinions.
2. Ask follow-ups only when genuinely ambiguous (section unclear, new category, factual gap) — batch questions, use defaults otherwise.
3. Publish directly (no `draft: true` unless he asks).
4. Add cross-site wiki links (`[[Note]]`, `[[Folder/main|Label]]` for sections) — this is expected, not optional. Give new notes an `aliases:` frontmatter list (natural phrases like "CompTIA Security+"), then retro-link: find exact mentions of the new subject in existing notes and convert those phrases into wiki links (wording untouched, edits reported).
5. Source images automatically: download covers into the vault folder (batch-ask permission first; `cover: https://…` URL as fallback). Books → Open Library; people → Wikimedia Commons only, license noted. Never random image results, never AI portraits of real people.
6. Factual notes (People, current events) end with a `## Sources` section (2–4 links used for verification). Skip for opinion/shelf/music notes.
7. Translate ALL content, both languages: `title_uk:` in frontmatter AND a full professional Ukrainian body in a sibling `<name>.uk.md` (posts) / `main.uk.md` (sections), body-only, same structure/links/embeds. A note without its `.uk.md` is unfinished. See `docs/CONTENT-WORKFLOW.md → Translation`.
8. Offer a diagram when a post/project would benefit; generate it as a self-theming `.svg` (see `docs/CONTENT-WORKFLOW.md` → Diagrams). Never hand-author Excalidraw scene JSON.
9. Write to `vault/<Section>/<Natural Title>.md` — or the matching subfolder where one exists (`vault/Shelf/Books/…`, `vault/Shelf/Movies|Shows|Videos/…`), its cover in that folder's `covers/`; loose media goes in the section's `attachments/`. Then report path, future URL, links added, images fetched + sources, and anything you fixed or assumed.

## Common tasks

- **New page style** (e.g. projects grid): see `docs/ADDING-PAGE-TYPES.md`. Component in `components/lists/`, register in `lib/section-types.tsx`, set `type:` in the section's `main.md`.
- **Any UI work**: wrap the route's content in `<Page>` (never re-type a container), reach for the tokens rather than literals, give clickable things `press` (`press press-soft` for cards), and don't add `transition-colors` beside `.press` — it declares its own. Then check the result in **both languages, light and dark**.
- **Editing `globals.css`**: it has no `@layer`, so position is the tie-breaker — an override belongs BELOW what it overrides. This has caused four separate bugs (`docs/DECISIONS.md` #51, #52, #55, #81), the subtlest being a `transition:` shorthand hundreds of lines above silently resetting a later `transform`. **A bare class selector here also beats a Tailwind utility of the same specificity**, so never set `position`, `display` or `width` on a class whose element carries a utility for it — `.chrome-bar { position: relative }` overrode `fixed` and dropped the floating breadcrumb into the page flow at full width (#81).
- **Verify changes**: `npm run build` must pass — it statically generates every page and will surface broken content/code. `npm test` runs Node's own runner (no framework) over `lib/*.test.ts` **and `scripts/*.test.mjs`**; it is wired through `--import ./scripts/test-hooks.mjs`, which registers `scripts/test-resolve.mjs` on the loader thread to teach it the `@/` alias and extensionless imports. `npm run validate:image-notes` gates both `predev` and `prebuild`, so a broken image note fails `dev` and `build` before Next.js starts.
- **Verifying a Tailwind class actually shipped**: grep the built CSS for the ESCAPED form (`.w-\[calc\(…\)\]`), or read the element's computed style. A plain grep finds nothing whether or not the rule exists, and "nothing" looks exactly like "never emitted" — that misreading is written up in `docs/DECISIONS.md` #54.

## SEO & feeds

- `app/sitemap.ts`, `app/robots.ts`, `app/feed.xml/route.ts` (RSS for Posts) — all statically generated. Site origin: `siteUrl` in `lib/site-config.ts`.
- Every page sets its own `<link rel=canonical>` + `og:url` through `pageMeta()` in `lib/metadata.ts`; notes also get `og:type=article` with `article:published_time`. Without a canonical the `?lang=uk` links `SelectionLink` hands out are indexable duplicates. `pageMeta()` re-declares the RSS link and `og:site_name` because Next REPLACES `alternates`/`openGraph` rather than merging them.
- Identity: `socials` in `lib/site-config.ts` is the ONE list of the owner's accounts, and both machine-readable claims read it — `rel="me"` on every icon link (`components/SocialLinks.tsx`, the IndieWeb claim Mastodon checks) and `sameAs` in the JSON-LD (the search-engine one, which drops the `mailto:` since it isn't a profile). Never put someone else's profile in that list: it would inherit `rel="me"` and claim to be them.
- JSON-LD in `lib/jsonld.ts`: `siteJsonLd()` (Person + `sameAs` socials, WebSite) in the layout, `entryJsonLd()` per note, `breadcrumbJsonLd()` on section and entry pages (home has none — it's the root of every trail).
- OG images generated at build via `next/og` — shared renderer in `lib/og.tsx`, route files `app/opengraph-image.tsx` + per-section + per-entry. Shelf entries get a split card with their own cover art (2:3, or 16:9 for videos) plus the author line; `ogCover()` inlines vault images as data URLs (relative paths don't resolve at build time) and returns undefined for anything Satori can't decode, so the note quietly falls back to the text card. See `docs/DECISIONS.md` #57.

## Features to know about

- **Sidebar, two ways in** (`components/Chrome.tsx`, `docs/DECISIONS.md` #74): the panel icon opens the drawer by click, and putting the pointer on the left edge of the window (`.edge-zone`, a 16px strip, `(hover: hover) and (pointer: fine)` only — on touch it would swallow the back-swipe) opens it too. `openBy` (`"modal" | "peek" | null`) records WHICH KIND, because they mean different things: a deliberate open — the icon, or the `m` key — is modal (backdrop, focus trapped, stays until dismissed), the edge is a peek (no backdrop, not `aria-modal`, focus untouched, closes ~180ms after the pointer leaves the panel — delayed so clipping the corner doesn't slam it shut, and it stays open if the keyboard is inside). Clicking the icon (or pressing `m`) while peeking PROMOTES it to modal rather than closing.
- **First-visit intro** (`components/Intro.tsx` + a gate script in `app/layout.tsx`, maths in `lib/intro.ts`, `docs/DECISIONS.md` #79): a reader's FIRST EVER visit to home opens on an empty page with the greeting typing itself; the photo fades in the moment the first name lands, and a beat after the full stop the rest of the page sweeps in line by line and the chrome fades up. Once per browser (`INTRO_KEY = "intro-seen"` in localStorage — clear it to see the intro again). The REAL `<h1>` is what types: it's split into `.tw-c` per-character spans in place and reassembled as a plain text node at the end, so the sentence is never duplicated in a component where it would drift from `vault/Home/main.md`. Untyped characters keep `visibility: hidden`, so the line never rewraps mid-type. The photo is cued by `photoCue()` finding the first name in the sentence, NOT by a character count — it survives rewording and works in Ukrainian, and returns Infinity (photo arrives with the body) if the greeting doesn't say the name. Everything is hidden by CSS keyed to `data-intro` on `<html>` and nothing is hidden in the HTML, so no-JS, crawlers and Reader mode get the whole page; `prefers-reduced-motion` never arms it. Three independent ends: any click/key/scroll/touch, the driver's own completion, and an 8s failsafe plus early pointer/key listeners in the gate script — a hidden page must always come back, including before hydration exists. Matching is by name (case/space-insensitive) and **vault-wide**, so a series can run across sections; no route or URL changes. Order is oldest-first, overridable per note with `part: 2` (for same-day or backdated parts). `series_uk:` is written on any ONE part and used for all. A series with a single published part renders nothing. See `docs/DECISIONS.md` #42.
- **Link hover previews**: internal links in `.prose` show a preview card on hover — title, excerpt, date, cover — from `getLinkPreviews()` in `lib/previews.ts`. Mounted per page (home, section, entry) with `previewsInHtml()`, which scans that page's rendered HTML and passes only the previews it can actually use — the layout used to hand every page all of them. Pointer devices only; the card is non-interactive. The cover **floats** and the excerpt wraps under it, sized from the image's own `coverAr` (intrinsic w/h, via `dimsFor()`) inside an 80 × 84 box — every cover keeps its true shape, from a 0.60 paperback to the square People portrait to a 5:1 logo banner, and a cover that can't fit shrinks rather than being cropped. **Nothing inside the card may take `overflow` or `display: -webkit-box`**: either makes its own formatting context, which sits beside the float instead of flowing round it, so the title/excerpt line clamps are gone and `EXCERPT_CHARS` (140) is what bounds the card's height. A card with NO cover shrinks to its text (`fit-content`, 13rem floor, 20rem ceiling) so a one-line section description isn't a 320px slab; one WITH a cover takes the ceiling via `data-cover` on the card, because a floated cover is out of flow and contributes nothing to `fit-content` — measure the text alone and the artwork gets squeezed into the remainder. `docs/DECISIONS.md` #85.
