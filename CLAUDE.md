# CLAUDE.md — AI assistant context

Context file for AI models working on this repo. Read this first, then `docs/ARCHITECTURE.md`.

## What this is

Kyrylo's portfolio site, published from an Obsidian vault. The `vault/` folder IS the CMS: TOP-LEVEL folders → section pages, `.md` files inside them → entries with their own URLs. Pipeline: Obsidian Git → GitHub → Vercel auto-deploy. Fully static (SSG), no database, no runtime fs access.

Sections may hold subfolders (`vault/Shelf/Books/`, `vault/Shelf/Books/covers/`, `vault/Posts/attachments/`) — they're filing, for the owner's benefit in Obsidian. A subfolder never becomes a page and never appears in a URL: an entry's slug comes from its file name, so a note can move between folders without breaking its address.

## Owner context

- Kyrylo, high-school student in Ontario, heading into cybersecurity (Security+, then Cyber Science at TMU). Not a professional developer — keep changes simple, documented, and low-maintenance.
- Design reference: brianlovin.com (sidebar rail, list-detail, near-black dark mode). Original implementation, inspired only.

## Hard rules

1. **Never make content edits outside `vault/`** unless asked — content belongs to the owner via Obsidian.
2. **Keep the site fully static.** No runtime fs reads, no server actions for content. Everything resolves at build time via `generateStaticParams`.
3. **Keep `vault/` conventions stable** (top-level folder + `main.md` = section; other `.md` = entries, at any depth inside it). Breaking these breaks the owner's Obsidian workflow.
4. **Update `docs/DECISIONS.md`** when you make a non-obvious architectural choice.
5. Assets: never reference vault files directly from components — they're mirrored to `public/vault-assets/` by `scripts/sync-assets.mjs` (runs via predev/prebuild).
6. **Two agents work here.** Keep `CLAUDE.md` and `AGENTS.md` in step, and never leave the tree half-edited — see below.

## Two agents work on this repo

Claude Code and Codex are both used here, on the same checkout. Each auto-loads its own file:

|---|---|---|
| `CLAUDE.md` | Claude Code | The full reference. Owns feature detail and conventions. |
| `AGENTS.md` | Codex | A thin always-loaded map that defers here for detail. |

- **Code and `docs/DECISIONS.md` are the source of truth.** Where prose disagrees with the code, the code wins — say so rather than "fixing" the code to match a stale sentence.
- **Change a convention, command, or invariant → update BOTH agent files in the same change**, plus `docs/DECISIONS.md` if the choice is non-obvious. These two files have already drifted apart once (each described a different `npm test` wiring), which is exactly the failure this rule prevents.
- **`AGENTS.md` must not restate feature detail** that this file owns — it should point here instead. Duplicated prose is what drifts.
- **One agent at a time in this working tree.** Obsidian Git auto-commits *everything* (`autoCommitOnlyStaged: false`) every 10 minutes and pushes, and Vercel deploys the result — so a half-finished edit publishes itself on a timer. Finish and verify a change, or work in a separate `git worktree`. Don't run Claude and Codex against this checkout simultaneously.
- **Check `git status --short` before editing.** Uncommitted changes you don't recognise may be the other agent's or the owner's in-flight work: leave them alone and ask. Never `git restore`, `git checkout --`, or `git stash` a file you didn't change yourself.

## Conventions

- Home is the section whose slug is `home` (`app/page.tsx`); `lib/section-types.tsx` is the registry mapping a section `type` to its list component.
- Icons (`components/icons.tsx`) are **rendered in the sidebar only** — no icons on page content (#64). `resolveIcon()` maps vault frontmatter emoji/names → SVGs; unknown emoji render as text.
- Frontmatter (section `main.md`): `title`, `icon`, `order`, `description`, `type`, `slug` (override), `draft`. Full frontmatter is exposed as `section.meta` so section types can define their own keys (e.g. `music` reads `playlists:`).
- Section types: `posts` (default; category filter chips from entry `category:` frontmatter — chips are links to `/posts?category=X`, read by `useSearchParams()` in `PostListClient`, so a post's own category chip lands here pre-filtered. Unlike the shelf these are NOT separate pages: no per-category title/OG/sitemap entry, and filtering needs JS), `music` (Apple Music iframe embeds — `lib/apple-music.ts`, no API key), `people` (cover-image grid; entry `cover:` frontmatter, initials fallback), `shelf` (Netflix-style: one horizontally-scrolling row per medium, each linking to `/<section>/type/<medium>`; entry `cover:` + `author:` + `medium: book|movie|show|video` (omit it and the subfolder decides — a note in `Shelf/Movies/` is a movie; `entryMedium()` in `lib/shelf.ts`) + optional `rating: 0–5` halves allowed + optional `coverFit: contain` + optional `status: reading` (also `watching`/`current`/`in-progress`) which badges the cover "Reading" or "Watching" depending on the medium — anything else, or no key at all, reads as finished and stays unlabelled; alias `books`. `medium: video` + `video: <youtube url>` renders a 16:9 card with a play badge and derives the thumbnail from the video ID — no `cover:` needed; optional `uploaded: YYYY-MM-DD` (the VIDEO's publish date, not the day it was shelved) is what upgrades the page's JSON-LD from `CreativeWork` to a full `VideoObject` — the site can't derive it, so without it the video markup is deliberately not emitted (`docs/DECISIONS.md` #41). Row order and grouping live in `lib/shelf.ts`. Every row is the same height: `--shelf-card-h` on `.shelf-row` (190px, 170px below 480px — deliberately between the old 225 cover row and 158 video row, so neither is dragged to the other) and the card WIDTH derives from it via `.shelf-card-tall` / `.shelf-card-wide` (hand-written, so the arithmetic sits beside the variable it reads). Videos keep their native **16:9**, uncropped, and are made smaller instead: `--shelf-video-h` is two thirds of `--shelf-card-h` (~226 × 127 vs ~127 × 190 for a cover), so the video row is shorter than the cover rows by a fixed ratio rather than by accident (`docs/DECISIONS.md` #54). Grid pages are unaffected; there the column width leads. `categories: [Tech, Education]` (multi-valued) drives filter chips on the medium page and renders as `#tags` at the END of the entry's metadata line, not on a row of their own — the section page shows neither), `projects` (TIL-style inline feed; async list component), `now` (nownownow-style page: a “Short-term goals” checklist plus an optional résumé, both written as MARKDOWN IN THE BODY and parsed by `lib/now-content.ts` into the `goals`/`resume` shapes the components read — `## Goals` is a task list (`[x]` = done, indented bullet = sub-label, trailing `→ [[Note]]` = link), `## Résumé` is a summary paragraph + one `###` per block + one `#### Role · Org` per timeline row with `*period* · sub-label #current` on that same line. Frontmatter keeps flat keys only: `updated:`/`updated_uk:`, `resume_file:`. Ukrainian goes in a sibling `main.uk.md` with the same structure, merged by position; flags and links are read from `main.md`. Anything above the first heading renders as intro prose. See Features + `docs/DECISIONS.md` #26). Markdown pipeline also auto-embeds standalone Apple Music and YouTube links (`lib/youtube.ts`, served from youtube-nocookie.com; handles watch/youtu.be/shorts/live URLs).
- Filterable lists are split server/client: `PostList`→`PostListClient` (server slims entries to serializable rows). The shelf is fully server-rendered — medium rows replaced its filter chips, so it needs no client state.
- Design is monochrome: no blue accent in hovers/active states. **There is no `--accent` token** — deleted after four passes trying to find the right amount of one colour (`docs/DECISIONS.md` #64). State chips, the ToC marker, `[progress::]` and reading bars, focus rings, the selection wash and action links all use `--text`: on a page with no other colour, full text colour IS the emphasis. Callouts keep their four hues (there colour carries meaning), and the hover-only exceptions stay. Active chips/nav use text-on-bg inversion. Two sanctioned exceptions, both hover-only so the page at rest is unchanged (`docs/DECISIONS.md` #56): people photos sit at `grayscale(0.3)` (`.person-photo`) and return to full colour, and the four platform icons take their brand colour (`.social-link[data-social]`, `--brand`, with near-white stand-ins for GitHub/X in dark mode; mail has no platform, so it keeps `var(--text)`). `@media (hover: none)` drops the photo filter — on touch there'd be no way back.
- Entry frontmatter is exposed as `entry.meta` (same pattern as `section.meta`) for type-specific keys.
- Frontmatter (entries): `title`, `date` (YYYY-MM-DD), `description`, `slug`, `draft` (or `published: false`), `series` (+ optional `series_uk`, `part`).
- Sized image embeds ≤128px (e.g. `![[me.jpeg|93]]`) render as circular avatars (`.avatar` class); larger sizes keep the rounded-rectangle style.
- The `posts` list groups entries by year (empty years never render); row dates are DD.MM. This date treatment is posts-only — other types show full dates.
- The `projects` list truncates entries over 1000 markdown chars; "Continue reading" links to the entry's own page.
- Breadcrumb names the current page's ANCESTORS, not itself ("Kyrylo · Posts" on a post) — the page's own title is already its `<h1>`. Each part is clickable. On home, and on a section's own page, only the site name remains. The section is the only ancestor at any depth: a shelf medium and its category pages all read "Kyrylo · Shelf", since they're one page with a different chip pressed and naming the medium both repeated the `<h1>` and changed the trail's shape as you filtered (#65).
- Slugs: `slugify()` in `lib/vault.ts` — keep stable, changing it breaks URLs.
- Styling: Tailwind utility classes + CSS variables in `app/globals.css`. Markdown output is styled by the hand-written `.prose` classes there. Dark mode is `prefers-color-scheme` only — no manual toggle. See the Design system section below before writing any CSS.

## Design system

Full reference: `docs/ARCHITECTURE.md` → Design system. The short version:

- **Never re-type a page container.** `components/Page.tsx` owns measure, gutters and rhythm (`--measure`, `--gutter`, `--page-y`). It used to be `max-w-2xl px-6 py-14 lg:py-24` copy-pasted into seven route files, two of which had already drifted (`docs/DECISIONS.md` #58).
- **Use the tokens, don't type literals** (#58). Radius `--r-xs|sm|md|lg|xl|full` (4/6/8/12/16px + pill, equal to Tailwind's scale so the two can't drift). Motion `--ease` + `--dur-fast|--dur|--dur-slow` (120/200/320ms; Tailwind's `--default-transition-*` point at them, so utility classes move the same way). Surfaces: `--surface` is a card/cover/badge FILL, `--bg-hover` is the pointer response, `--chrome-bg`/`--chrome-ring` are the floating bars and pills (built from `--surface` in dark mode — a pill made of `--bg` is invisible on a dark page, `docs/DECISIONS.md` #60).
- **`.press`** (#55) dips a control to 97% while held; `.press-soft` (99%) for cards. Opt-in — a scaled inline prose link reads as a rendering fault. Named components join by selector at the very END of `globals.css`; don't move that block up.
- **The design itself** lives in one block at the FOOT of `globals.css` (`docs/DECISIONS.md` #59): Source Serif 4 for everything except code (sidebar and `svg.diagram text` included), big fluid `.page-title`, wide tonal range, dark mode with real elevation (`--surface` above `--bg`), demoted `.entry-meta`/`.entry-tags`, generous space above `h2`. It shipped as one of two switchable themes while the choice was being made; the switch and the losing design are deleted.
- **Any new UI must work in both languages, light and dark, and under `prefers-reduced-motion`.** Using the tokens is what makes that nearly free.
- **One typeface — Source Serif 4, everything except code**, self-hosted via `next/font` with the `cyrillic` subset AND `axes: ["opsz"]` (#61). Script coverage is a hard filter applied before a typeface is judged on looks: every note has a Ukrainian translation, and Newsreader was chosen and dropped for exactly this (#59). Quotes are the same family in italic — don't reach for a second family, that's what Lora was and it had to go.

## Content intake (most common task)

When Kyrylo hands you raw content (a post, book/movie thoughts, a project
update), follow **`docs/CONTENT-WORKFLOW.md`** — the full playbook. Core rules:

1. Light-touch editing only — fix typos/grammar/structure, never his voice or opinions.
2. Ask follow-ups only when genuinely ambiguous (section unclear, new category, factual gap) — batch questions, use defaults otherwise.
3. Publish directly (no `draft: true` unless he asks).
4. Add cross-site wiki links (`[[Note]]`, `[[Folder/main|Label]]` for sections) — this is expected, not optional. Give new notes an `aliases:` frontmatter list (natural phrases like "CompTIA Security+"), then retro-link: find exact mentions of the new subject in existing notes and convert those phrases into wiki links (wording untouched, edits reported).
5. Source images automatically: download covers into the vault folder (batch-ask permission first; `cover: https://…` URL as fallback). Books → Open Library; people → Wikimedia Commons only, license noted. Never random image results, never AI portraits of real people.
6. Factual notes (People, current events) end with a `## Sources` section (2–4 links used for verification). Skip for opinion/shelf/music notes.
7. Translate ALL content, both languages: `title_uk:` in frontmatter AND a full professional Ukrainian body in a sibling `<name>.uk.md` (posts) / `main.uk.md` (sections), body-only, same structure/links/embeds. A note without its `.uk.md` is unfinished. See `docs/CONTENT-WORKFLOW.md → Translation`.
8. Offer a diagram when a post/project would benefit; generate it as a self-theming `.svg` (see `docs/CONTENT-WORKFLOW.md` → Diagrams). Never hand-author Excalidraw scene JSON.
9. Write to `vault/<Section>/<Natural Title>.md` — or the matching subfolder where one exists (`vault/Shelf/Books/…`, `vault/Shelf/Movies|Shows|Videos/…`), its cover in that folder's `covers/`; loose media goes in the section's `attachments/`. Then report path, future URL, links added, images fetched + sources, and anything you fixed or assumed.

## Common tasks

- **New page style** (e.g. projects grid): see `docs/ADDING-PAGE-TYPES.md`. Component in `components/lists/`, register in `lib/section-types.tsx`, set `type:` in the section's `main.md`.
- **Any UI work**: wrap the route's content in `<Page>` (never re-type a container), reach for the tokens rather than literals, give clickable things `press` (`press press-soft` for cards), and don't add `transition-colors` beside `.press` — it declares its own. Then check the result in **both languages, light and dark**.
- **Editing `globals.css`**: it has no `@layer`, so position is the tie-breaker — an override belongs BELOW what it overrides. This has caused three separate bugs (`docs/DECISIONS.md` #51, #52, #55), the subtlest being a `transition:` shorthand hundreds of lines above silently resetting a later `transform`.
- **Verify changes**: `npm run build` must pass — it statically generates every page and will surface broken content/code. `npm test` runs Node's own runner (no framework) over `lib/*.test.ts` **and `scripts/*.test.mjs`**; it is wired through `--import ./scripts/test-hooks.mjs`, which registers `scripts/test-resolve.mjs` on the loader thread to teach it the `@/` alias and extensionless imports. `npm run validate:image-notes` gates both `predev` and `prebuild`, so a broken image note fails `dev` and `build` before Next.js starts.
- **Verifying a Tailwind class actually shipped**: grep the built CSS for the ESCAPED form (`.w-\[calc\(…\)\]`), or read the element's computed style. A plain grep finds nothing whether or not the rule exists, and "nothing" looks exactly like "never emitted" — that misreading is written up in `docs/DECISIONS.md` #54.

## SEO & feeds

- `app/sitemap.ts`, `app/robots.ts`, `app/feed.xml/route.ts` (RSS for Posts) — all statically generated. Site origin: `siteUrl` in `lib/site-config.ts`.
- Every page sets its own `<link rel=canonical>` + `og:url` through `pageMeta()` in `lib/metadata.ts`; notes also get `og:type=article` with `article:published_time`. Without a canonical the `?lang=uk` links `SelectionLink` hands out are indexable duplicates. `pageMeta()` re-declares the RSS link and `og:site_name` because Next REPLACES `alternates`/`openGraph` rather than merging them.
- Identity: `socials` in `lib/site-config.ts` is the ONE list of the owner's accounts, and both machine-readable claims read it — `rel="me"` on every icon link (`components/SocialLinks.tsx`, the IndieWeb claim Mastodon checks) and `sameAs` in the JSON-LD (the search-engine one, which drops the `mailto:` since it isn't a profile). Never put someone else's profile in that list: it would inherit `rel="me"` and claim to be them.
- JSON-LD in `lib/jsonld.ts`: `siteJsonLd()` (Person + `sameAs` socials, WebSite) in the layout, `entryJsonLd()` per note, `breadcrumbJsonLd()` on section and entry pages (home has none — it's the root of every trail).
- OG images generated at build via `next/og` — shared renderer in `lib/og.tsx`, route files `app/opengraph-image.tsx` + per-section + per-entry. Shelf entries get a split card with their own cover art (2:3, or 16:9 for videos) plus the author line; `ogCover()` inlines vault images as data URLs (relative paths don't resolve at build time) and returns undefined for anything Satori can't decode, so the note quietly falls back to the text card. See `docs/DECISIONS.md` #57.
- Favicon: `app/icon.png` (circle-cropped from the owner's avatar) + `app/apple-icon.png`. Regenerate with PIL if the avatar changes.

## Features to know about

- **Sidebar, two ways in** (`components/Chrome.tsx`, `docs/DECISIONS.md` #74): the panel icon opens the drawer by click, and putting the pointer on the left edge of the window (`.edge-zone`, a 16px strip, `(hover: hover) and (pointer: fine)` only — on touch it would swallow the back-swipe) opens it too. `openBy` (`"modal" | "peek" | null`) records WHICH KIND, because they mean different things: a deliberate open — the icon, or the `m` key — is modal (backdrop, focus trapped, stays until dismissed), the edge is a peek (no backdrop, not `aria-modal`, focus untouched, closes ~180ms after the pointer leaves the panel — delayed so clipping the corner doesn't slam it shut, and it stays open if the keyboard is inside). Clicking the icon (or pressing `m`) while peeking PROMOTES it to modal rather than closing.
- **First-visit intro** (`components/Intro.tsx` + a gate script in `app/layout.tsx`, maths in `lib/intro.ts`, `docs/DECISIONS.md` #79): a reader's FIRST EVER visit to home opens on an empty page with the greeting typing itself; the photo fades in the moment the first name lands, and a beat after the full stop the rest of the page sweeps in line by line and the chrome fades up. Once per browser (`INTRO_KEY = "intro-seen"` in localStorage — clear it to see the intro again). The REAL `<h1>` is what types: it's split into `.tw-c` per-character spans in place and reassembled as a plain text node at the end, so the sentence is never duplicated in a component where it would drift from `vault/Home/main.md`. Untyped characters keep `visibility: hidden`, so the line never rewraps mid-type. The photo is cued by `photoCue()` finding the first name in the sentence, NOT by a character count — it survives rewording and works in Ukrainian, and returns Infinity (photo arrives with the body) if the greeting doesn't say the name. Everything is hidden by CSS keyed to `data-intro` on `<html>` and nothing is hidden in the HTML, so no-JS, crawlers and Reader mode get the whole page; `prefers-reduced-motion` never arms it. Three independent ends: any click/key/scroll/touch, the driver's own completion, and an 8s failsafe plus early pointer/key listeners in the gate script — a hidden page must always come back, including before hydration exists. The gate lives in the layout because only an inline `<head>` script runs before the first paint (hence its `pathname === '/'` check) and it writes `INTRO_KEY` itself so "armed" and "seen" are one decision; the client half covers soft navigations, which the gate never sees. `npm test` asserts the sequence stays inside the failsafe. **Three things here are load-bearing and were each a visible flash before review:** the heading is hidden outright until the driver adds `.tw` (otherwise the server's finished sentence paints, then vanishes when hydration runs); the chrome is hidden/revealed by NAME (`.skip-link`, `.chrome-bar`, `.edge-zone`) and never as `body > *:not(main)`, which also caught the drawer's `bg-black/25` backdrop and the closed dialogs and faded a dark sheet over the page on the way out — anything that manages its own visibility must be left to; and the character spans are NEVER reassembled, because one inline box per character breaks kerning across the boundaries and restoring the text node would make the title settle a pixel or two. Skipping fades over 160ms with the stagger dropped (`[data-intro-fast]`) rather than cutting.
- **Note constellation** (`components/Constellation.tsx` server → `components/ConstellationStrip.tsx` client, maths in `lib/constellation.ts`, `docs/DECISIONS.md` #80): the drawer's footer shows six months of writing as ONE BAR PER WEEK, height = that week's note count against the busiest week. Built at build time from every dated entry, so it never needs maintaining. It was a GitHub-style DAY grid first and that was thrown away after looking at the real vault through it — 25 notes on 5 days, 14 of them in one sitting, which reads as abandoned; the day a shelf note is typed isn't the day the book was read, and weekly buckets absorb that. `WEEKS = 25`, bars 6px + 1px gap = 174px, which is what fits the `w-56` drawer's 176px of inner width: **the bar width, the gap and `WEEKS` are one decision written in two files** and both say so. Height carries the count so tone doesn't (every bar the same weight — no ramp, monochrome, #64). The "N notes · 6 months" line is HIDDEN until `:hover`/`:focus-within`, and a bar's own summary takes that same line over on hover (opaque background, so no `:has()` needed). Clicking a bar opens THAT WEEK'S NOTES directly above the strip, IN FLOW and styled as the sidebar's own nav rows (`-0.75rem` pulls them out of the footer's `px-6` into the nav's `px-3` column; one size down because a note title is a sentence, not a word). It was a bordered/blurred popover first and that read as a separate app parked over the drawer; in flow it also needs no backdrop, which would have eaten the first click on every nav link under it. One list refilled per week, so no titles are in the page HTML until something is clicked; `inert` when closed, Escape or the same bar closes it. Bars are buttons, not links: that gives up the no-JS version deliberately, since a popover of choices has no honest static form in a 176px column. Rendered by `app/layout.tsx` and passed to `Chrome` as an ELEMENT — `Chrome` is a client component and importing it would pull `lib/vault.ts`'s `fs` into the browser bundle. `today` is a prop, never a clock read, so the strip is testable.
- **Drafts**: `draft: true` entries/sections are visible in `npm run dev` with an amber "Draft" badge, excluded from production builds (`SHOW_DRAFTS` in `lib/vault.ts`).
- **Wiki links** resolve across ALL sections via `getWikiIndex()` (file name, title, slug, or `aliases:` frontmatter — case-insensitive; aliases are Obsidian-native so links work in both places). Unknown targets fall back to same-section slug. For links to SECTION pages use `[[Folder/main|Label]]` — it resolves on the site AND opens the right file in Obsidian (bare `[[Now]]` would create a new note there).
- **Callouts**: Obsidian `> [!note] Title` → styled `.callout` divs (colors per type in globals.css).
- **Progress bars**: `[progress:: 45]` inline in any note → styled bar + percent label (plain text in Obsidian). Used on the Now page.
- **Diagrams**: `![[Drawing.excalidraw]]` embeds resolve to the Excalidraw plugin's exported SVG (theme-aware if light+dark exported); AI diagrams are self-theming `.svg` files embedded like images. **Self-theming SVGs are inlined into the page** (`inlineSelfThemingSvg` in `lib/markdown.ts`, styles namespaced to `#d-<filename>`) — through `<img>` the browser caches the rasterized image and freezes its `prefers-color-scheme` at first decode, so diagrams got stuck in the wrong theme. Two-file Excalidraw exports still use `<img>`. Resolver: `getAssetIndex()` in `lib/vault.ts` (basename→URL, vault-wide) + `resolveExcalidraw`/`diagramFigure`/`themedImg` in `lib/markdown.ts`. `.dark.<ext>` sibling → theme swap; `.uk.<ext>` sibling (or `Drawing.uk.excalidraw`) → language swap; caption `EN :: UK` splits by language. `.excalidraw.md` excluded from pages; `.excalidraw` JSON not shipped. Full guide: `docs/EXCALIDRAW.md`; AI workflow: `docs/CONTENT-WORKFLOW.md`.
- **Image notes**: a normal bilingual SVG or exported Excalidraw embed followed immediately by `<!-- image-note: original.jpeg -->` becomes one `.image-note` figure with a native-radio `Diagram / Original` switch (diagram first, no JS required). The source photo's build-time dimensions reserve one shared stage, so switching cannot reflow the article. Obsidian shows the diagram and hides the directive. Reconstruction adds one intake step to the ordinary semantic-SVG recipe: extract a source-faithful transcription map, then hand-author identical-geometry English/Ukrainian SVGs. Layout and obvious spelling may be cleaned up, but unsupported explanatory copy is forbidden and uncertainty is resolved or marked; keep one or two meaningful source cues so the result stays personal. Excalidraw is optional when the owner explicitly wants a visually editable drawing, not a required intermediate. The original phone photo is stripped of EXIF/GPS metadata and resized before entering the vault; both active views remain part of the lightbox gallery. `npm run validate:image-notes` blocks dev/build on missing bilingual assets, geometry/privacy/accessibility problems, unsafe SVGs, incomplete exports for a directly embedded Excalidraw drawing, or **a diagram over the 64KB inline ceiling** — past it the SVG silently degrades to an `<img>` and freezes in one theme, which is the one failure the reader would see and the build otherwise never mentions. Full workflow: `docs/CONTENT-WORKFLOW.md → Image notes`; renderer: `lib/markdown.ts → imageNoteHtml()`; validator: `scripts/validate-image-notes.mjs`.
- **Language toggle**: sidebar flag switch (English default / Ukrainian). `components/T.tsx` renders both languages as spans; CSS on `html[data-lang]` shows the active one (choice persisted in localStorage, restored pre-paint by inline script in `app/layout.tsx`). Titles translate via `title_uk:` frontmatter (`ukTitle()` in `lib/vault.ts`). Fixed UI strings live in `lib/ui-strings.ts` (`ui` dict of `{en, uk}` pairs — spread into `<T {...ui.key} />`; add a key there instead of hard-coding English). Dates: `displayDate` / `displayDateUk` wrapped in `<T>`. No routing, no double build. Section bodies use a sibling `main.uk.md` and entry bodies a sibling `<name>.uk.md` (read into `contentUk`, rendered in a `.lang-uk` block). Every note should carry its `.uk.md` translation — it's part of the content-intake workflow, not optional.
- **Figures/lightbox**: standalone images with alt text render as figure+figcaption; all non-avatar content images open in `components/Lightbox.tsx` on click.
- **Reading time**: `readingStats()` shown on posts-type entry pages only; the same `minutes` is passed to `ReadingProgress`, which shows a "N min left" pill bottom-right once you're 6% in (#46) — except below 640px, where the number is announced via the `timeleft` event and rendered inside the floating breadcrumb bar, sharing one grid cell with the breadcrumb and sliding vertically past it as you scroll down (#50, #53).
- **Contents scroll-spy** (`lib/toc-spy.ts`, `docs/DECISIONS.md` #76): the active row is the last heading above a reading line resting 140px down the window — and that line DESCENDS to the foot of the window over the page's final screenful, at the rate the scroll runs out. Without it the last viewport-height of every page is a dead zone whose headings can never reach the line, which on a tall screen is the whole tail of the rail. A page too short to scroll keeps the resting line (otherwise arriving would highlight its last heading). Maths in `lib/`, covered by `npm test`; `components/Toc.tsx` only measures and asks. The click-hold (`held`) is still needed — at the bottom several headings sit above the line, so the spy would answer with a later one than you clicked.
- **Contents pill on phones**: below 640px the ToC pill is the three-line icon alone, in the TOP-RIGHT corner, built to the same 2.5rem height as the floating breadcrumb bar opposite it; the sheet hangs under it, narrower (#51). Unchanged from 640px up. Every ToC row — rail and sheet, title row included — is ONE line, ellipsised via `.toc-link`, with the full text in its `title` tooltip.
- **Read notes** (`lib/read-notes.ts`): path → when you finished it, written by `ReadingProgress` once the bar passes `READ_AT` (92%), or on arrival for a note shorter than the viewport — such a note never moves the bar (`finishAt()` returns 0) and is entirely in front of the reader already, so opening it is the only signal there is. A different question from `ReadingPosition`, which stores a scroll offset and so can't tell a finished short note from an abandoned long one. `components/Series.tsx` reads it: a solid line grows along the badge's dotted underline, the panel counts parts read, and each row carries a **checkbox** — `markRead`/`unmarkRead`, because the automatic signal is a default, not a verdict (a part read on another device was never seen by this browser). Client-only — starts at zero and fills in after hydration; the `noteread` event keeps every reader of the store in step (#65).
- **Reading bar**: text pays out continuously, media (figures/embeds/diagrams) pays out in one step once fully passed and at half weight (`MEDIA_WEIGHT`) — so the bar *pauses* at each image instead of being driven by it. Read line is the viewport's TOP (so the opening still counts — measuring at the bottom made it worth 0%), finish line is the article's end reaching the viewport's bottom (`finishAt()`); a closing "Sources" heading ends the article early. Maths in `lib/reading-progress.ts`, covered by `npm test` (Node's own runner, no framework). Eases toward the scroll position with a glow at the leading edge; all motion off under `prefers-reduced-motion`.
- **Search**: Cmd/Ctrl+K palette (`components/CommandPalette.tsx`) over a build-time index from `getSearchIndex()`, served as one static file at `/search-index.json` (`app/search-index.json/route.ts`) and fetched by `components/useSearchIndex.ts` on the FIRST open — it used to be a prop and put every note's full text into every page. Still fully static, no backend. Every h2/h3 is indexed as its own jump-to-anchor result labelled with the note it's in; those ids are minted with `github-slugger` (what rehype-slug uses) rather than `slugify()`, which would strip Cyrillic and break every Ukrainian anchor. Heading results carry `lang` and only show in the matching language, since each language's heading has a different anchor.
- **Copy as Markdown**: icon button beside the entry title (`components/CopyMarkdown.tsx`) copying the note's raw vault source in whichever language is active. Clipboard fallback shared with the code-block buttons in `lib/clipboard.ts`.
- **Code blocks**: highlighted at build time by Shiki (`lib/highlight.ts` + the `rehypeCodeBlocks` step in `lib/markdown.ts`), wrapped in `<figure class="code-block">`. Optional filename header via ` ```bash title="scan.sh" ` (a bare `scan.sh` after the language works too). Shell fences (`bash`, `sh`, `console`, `zsh`, `powershell`… — `SHELL_LANGS`/`isShell()` in `lib/markdown.ts`) render as a terminal instead: `data-terminal` on the figure, three grey dots in the header, and a header even with no title. Dots are grey, not traffic lights — the page is monochrome and the shape already says terminal (#65). Languages must be listed in `LANGS` in `lib/highlight.ts` — unknown ones fall back to plain text. Copy button injected by `components/CodeCopy.tsx`. Zero client-side highlighting JS.
- **Résumé** (`components/Resume.tsx`): rendered under the goals checklist from the `## Résumé` section of `vault/Now/main.md` — summary, experience/education/certifications timelines, strengths, languages, contact. Ukrainian comes from `main.uk.md`, merged by position into the `_uk` fields (identical strings dropped — `T` renders English for both anyway); bullet strings use a `Label — detail` convention and the em dash splits the bold lead-in. `scripts/build-resume-pdf.py` renders the downloadable PDF from that same section, with its own English-only copy of the parser (`pip install weasyprint`, run by hand — deliberately not in `prebuild`). The PDF is public, so it carries email + city only — no phone number or street address anywhere in the repo. Its block list (Experience/Education/…) is defined once in `lib/resume.ts` and shared by the component, the Now page's `<Toc>` outline, and Cmd+K search (a dedicated "Résumé" result plus one per block, jumping to `#resume` / `#experience` / …). `/resume` redirects to `/now` (`next.config.ts`). See `docs/DECISIONS.md` #25.
- **Footnotes → sidenotes**: an ordinary Obsidian footnote (`[^1]`) renders as a note in the LEFT margin from 1280px up (the right gutter is the ToC's) and as the usual list at the bottom below that — both are in the HTML, CSS picks one. `rehypeSidenotes` in `lib/markdown.ts`; footnotes containing anything other than paragraphs stay bottom-only. See `docs/DECISIONS.md` #28.
- **Copy link to selection**: selecting prose raises a pill copying a `#:~:text=` deep link (`components/SelectionLink.tsx`), pointer devices only. It appends `?lang=uk` when the reader is in Ukrainian — that query param now overrides the stored language pre-paint, without overwriting it.
- **Lightbox gallery**: every visible figure on the page is one gallery; ← / → step through it (`components/Lightbox.tsx`). Below 640px the arrows sit beside the counter as "‹ 1 / 2 ›" instead of floating over the image (#53).
- **Analytics**: `@vercel/analytics` in the root layout — page views, no cookies. The layout also ships a `speculationrules` script that **prefetches** internal documents on hover — never `prerender`, which would run the page and make every hover count as a visit (`docs/DECISIONS.md` #33).
- **Keyboard shortcuts** (`components/Shortcuts.tsx`, mounted by `Chrome`): `[` / `]` prev/next entry (read from the entry footer's own links, not props), `j` / `k` down/up the page's list, `g h` home, `g 1…9` nth section in sidebar order, `l` language, `m` menu, `/` search, `?` cheat sheet. `m` shares `toggleMenu()` with the panel icon, so the keyboard opens the drawer MODALLY rather than as an edge peek — someone on the keyboard wants to arrow through the sections, which is what the focus trap is for (#75). Keys go through `shortcutKey()` (`lib/shortcut-key.ts`, `docs/DECISIONS.md` #77): `e.key` first, falling back to the Latin label of `e.code`, so a Cyrillic layout (where `l` types `д`) works AND punctuation reached by another key (`/` is Shift+7 on German) still works. `⌘K` in `Chrome.tsx` reads through it too; handlers that only want `Escape`/arrows don't need it. Covered by `npm test`, with the layouts as the cases. `j`/`k` find rows through `.stagger` (every list already carries it), skip the hidden language via `offsetParent`, and move real FOCUS rather than a painted selection — so Enter opens the row for free; `.list-focus` exists only because a programmatic `.focus()` isn't reliably `:focus-visible`, and it paints the same `--bg-hover` wash the pointer does (a row under the pointer and a row under the keyboard are the same state) with the ring suppressed. Never fires while a dialog is open, and doesn't swallow the key on a page with no list (#65).
- **Cmd+K opens onto recents**: `lib/recents.ts` keeps the last twelve visited paths in one localStorage key; an empty query leads with up to five of them (#46).
- **Cmd+K runs actions too**: switch language, copy page as Markdown (clicks the existing `button.copy-md`), copy link, open this note on GitHub (`repoUrl`/`repoBranch` in `lib/site-config.ts`; path read from `data-vault-source` on the entry page), random note. Pages always sort above actions. A leading `>` scopes the search to the current page and its headings; `>` alone prints the note's outline.
- **Reading position** (`components/ReadingPosition.tsx`): remembers how far into a note you got and *offers* to return — never scrolls on its own. One localStorage key, map of path → position, pruned to 20 notes / 30 days, written on a debounce rather than per scroll frame. The offer withdraws on reader-generated scrolling (`wheel`/`touchmove`/scroll keys), NOT on a scroll threshold (#47), and is only made when you land more than half a screen from the saved mark — landing ON it means the browser already did the job (#49). Add `?rp=debug` to any note's URL to print why the offer was or wasn't made (#48).
- **Image dimensions**: `sync-assets.mjs` writes `.image-manifest.json` (blur placeholder + `w`/`h` per raster); `rehypeImageSize` in `lib/markdown.ts` stamps `width`/`height` on content images so nothing shifts as they load. Explicitly sized embeds (`![[me.jpeg|93]]`) keep their size.
- **Responsive images**: `sync-assets.mjs` also writes 256/672/1344px WebP copies beside each raster (never touching the originals) and a ready-made `srcset` into the manifest. `rehypeImageSize` stamps it on content images with a `sizes` matching the prose column (or the embed's own width); shelf and people covers carry it via `coverSrcSet`. `srcSetFor()` in `lib/blur.ts`.
- **Motion that answers** (#66): an arrow leads on hover and is thrown in its direction on press and STAYS thrown — `components/ArrowThrow.tsx` adds `.is-thrown` at the click, because `:active` ends before the next page paints and the arrow used to race back (`Shortcuts` adds the same class for `[`/`]`). `.sibling-arrow` in the entry footer, `.arrow-glyph` on standalone action links (`.action-link`: "Continue reading", "All posts", "← Back home" — `.is-back` leads and throws the other way); arrows live in spans, never inside a translated string; the lightbox arrows throw shorter and don't fade, since you stay in the gallery. Checkmarks DRAW (`stroke-dasharray`, paths written short-arm-first so the stroke runs the right way) — an animation on the copy button, which goes from `display:none`, a transition on the always-mounted series checkbox. Prose links (`p`/`li`/`blockquote`/`td` only) sweep their underline from the left using two background gradients — `text-decoration` can't grow from one end, and the trade-off is losing `skip-ink`, so the rule sits below the descenders and everything else keeps the plain decoration. The Cmd+K selected row is one `.palette-marker` that slides, measured from the live DOM like the ToC marker.
- **Motion** (`docs/DECISIONS.md` #38, #44, #45): `.stagger` on a list container makes its children arrive one at a time (nth-child delays, capped at 12; `animation: none` under reduced motion and print, since a shortened duration still honours the delay). Navigations fade via `.page-in` — they briefly ran through the View Transitions API and it was reverted for feeling laggy (#45); the API survives only in the lightbox, which opens as a zoom out of the figure you clicked (`lib/view-transition.ts`). Shelf rows are drag-to-scroll, no edge fade and no arrows (`components/lists/ShelfRow.tsx`). A fixed `feTurbulence` tile on `body::after` grains the background. The ToC rail highlight is one sliding `.toc-marker` positioned from the live DOM. Dialogs (palette, shortcut sheet, ToC sheet) stay mounted and toggle `data-open` so they animate shut, with `inert` when closed and contents gated behind first open to keep them out of every page's HTML. **Pressed state** (#55): `.press` dips a control to 97% while held (`.press-soft` → 99% for cards, via `--press-scale`) — opt-in, because a scaled inline prose link reads as a rendering fault; the named components join in by selector at the very END of `globals.css`, since their own `transition:` shorthands sit hundreds of lines above and would otherwise reset transform away. `.lightbox-arrow`/`.selection-pill` compose the press with the transform they're positioned by.
- **Series** (`lib/series.ts` + `components/Series.tsx`): `series: Road to Security+` in an entry's frontmatter joins it to a multi-part arc — a "Part 2 of 5" badge beside the date which opens a popover listing every part (built like the mobile ToC sheet: always mounted, `data-open`, `inert` when closed, contents gated behind first open; anchored under the badge at every width, nudged left by a measurement when it would overflow the window). Matching is by name (case/space-insensitive) and **vault-wide**, so a series can run across sections; no route or URL changes. Order is oldest-first, overridable per note with `part: 2` (for same-day or backdated parts). `series_uk:` is written on any ONE part and used for all. A series with a single published part renders nothing. See `docs/DECISIONS.md` #42.
- **Link hover previews**: internal links in `.prose` show a preview card on hover — title, excerpt, date, cover — from `getLinkPreviews()` in `lib/previews.ts`. Mounted per page (home, section, entry) with `previewsInHtml()`, which scans that page's rendered HTML and passes only the previews it can actually use — the layout used to hand every page all of them. Pointer devices only; the card is non-interactive.
